# 切り順（sequencing）特徴 — Top-1 は明確に改善、勝率は動かず（2026-08-05）

> **状態: 有効（結論確定）** — これまでで最大の Top-1 改善（+0.84pt・完全分離）が、
> 勝率をまったく動かさなかった。**Top-1 を採否の指標に使わない**ことの決定的な実例。

## 1. 何を試したか

ポケカの「切り順」のセオリーを方策の入力に落とし込んだ。

### 学んだセオリー

根底にある原則は一つ。**不確定情報に関わる行動を先に、確定情報だけの行動を最後に。**
そこから具体的なルールが導かれる（出典は §7）。

| ルール | 理由 |
|---|---|
| ドロー系 → サーチ系 の順 | 引いた結果を見てからサーチを使えば温存できる |
| サーチ同士なら当たり確率の低いものから | 例: スーパーボール → キャプチャアロマ → ハイパーボール |
| 山札圧縮を先に | 山札を減らしてから引くと当たる確率が上がる |
| 複数枚必要ならドロー優先 | 失敗したときだけサーチを使う |
| 手張り・ベンチ出し・逃げは最後 | 自分の手札情報だけで完結する確定行動だから |

### 診断との対応

誤答の分解（→ [bc-retrain-2026-08-03.md](bc-retrain-2026-08-03.md)）で、
**誤答の最大の塊が `play→play` 2,516件**（カードを使うことは合っていて、どれを使うかで外す）
と分かっていた。上のセオリーはまさにその順番を決めるルールにあたる。

### 気づいた構造上の欠落

方策は**選択肢を1個ずつ独立にスコアリング**している（pointwise）。共有されるのは状態ベクトルだけで、
**他にどんな選択肢があるかを見ていない**。

上のルールはすべて「いま選べる手の中での相対順序」であり、
「ドローを先に」は**サーチも選べる状況でなければ意味を持たない**。
つまり従来の方策は、セオリーの中核を**表現する手段そのものを持っていなかった**。

## 2. 実装

`OPTION_FEATURE_NAMES` に14次元を追加（65 → 79）。状態側は 166 のまま。
選択肢側に置いたのは、相対順序の情報は選択肢ごとに値が変わる形のほうが直接効くため。

```
opt_role_draw / opt_role_search / opt_role_deck_look   この選択肢の役割
opt_is_deterministic                                   手張り/逃げ/終了 = 確定行動
opts_n_draw / opts_n_search / opts_n_deck_look /
opts_n_deterministic                                   他に何が使えるか
opts_same_opttype_count                                同種の選択肢の数
opt_hand_copies                                        このカードを手札に何枚持つか
hand_n_draw / hand_n_search /
hand_n_energy_accel / hand_n_hand_disrupt              手札の中身
```

役割判定は新規の `ptcg_ai/shared/card_roles.py` が `CardData.skills[].text` から行う。
実デッキで検証済み（ボール系＝search、リーリエの決意＝draw、
ふしぎなアメ・ボスの指令＝役割なし＝確定行動）。

**モデル構造は変えていない。** 隠れ層があるので状態側と選択肢側は相互作用し、
集合サマリを手作業で pooling して各選択肢に配る形（DeepSets の手作り版）で表現力は足りる。

## 3. 結果

対照群は `--ablate-features` で同14次元を 0 で潰したもの。
**次元・データ・凍結プールはすべて同一で、情報の有無だけが違う。** 各3シード。

### Top-1（副次指標）— 明確に改善

| | seed42 | seed1 | seed2 | 平均 | 幅 |
|---|---:|---:|---:|---:|---:|
| 実験群 | 0.7424 | 0.7451 | 0.7463 | **0.7446** | 0.004 |
| 対照群 | 0.7350 | 0.7369 | 0.7368 | 0.7362 | 0.002 |

**+0.84pt。実験群の最小値が対照群の最大値を上回る完全分離。** NLL も 0.7245 → 0.7088。

教師の一致率の天井は 0.7685（同一盤面で多数派を必ず当てた場合の上限）。
対照群からの残り 3.23pt のうち **0.84pt（26%）を埋めた**ことになる。
容量拡大も、にげるコスト追加も、この指標を動かせなかった。

### 勝率（主指標）— 差なし

新プール（4アーキタイプを同特徴で学習）に対し、学習なしで各1,200試合。

| | 各シードの勝率 | 平均 | n |
|---|---|---:|---:|
| 実験群 | 0.574 / 0.559 / 0.574 | 0.5692 | 3,600 |
| 対照群 | 0.579 / 0.566 | 0.5725 | 2,400 |

**差 −0.3pt、p=0.798。** 各シードの散らばりが完全に重なっている。
δ_min=0.03 を検出できる設計なので、検出力不足ではなく**「差が無い」と言い切れる**。

（対照群の3本目はキュー待ちのまま打ち切り。差が p=0.80 と大きく離れており結論は変わらない。）

## 4. 解釈

**上位プレイヤーの切り順の癖を精度良く真似られるようになったが、その切り順は勝敗をほとんど左右していない。**

セオリー通りの順番で切ることは「間違いではない」が、勝敗を分けるほどの差は生まない、
ということだと考えられる。少なくともこの相手プール・この試合数では。

もう一つの可能性として、**切り順の誤りが勝敗に効く局面がそもそも少ない**ことも考えられる。
セオリーは「損をしない」ための規律であって、勝ち筋を作る類のものではない。

## 5. この実験から言えること（重要）

**Top-1 一致率を採否の指標に使うのは、もうやめるべき。**

チームは以前から「offline は上がるが実戦に転移しない」を記録してきた
（`sample_submission/docs/plans/measurement-protocol/design.md` §0.1）。
本実験は**その最も明確な実例**になった。これまでで最大の Top-1 改善が、勝率をまったく動かしていない。

以後、特徴量の採否は**勝率のみ**で判断する。Top-1 は「どこが弱いか」の診断にのみ使う。

## 6. 採否と、残すもの

**不採用。** 害は無いが、有益でもない。次元を14増やす保守コストが残るだけ。

ただし **`ptcg_ai/shared/card_roles.py` は残す価値がある。**
カードを役割（ドロー/サーチ/山札確認/手札干渉/エネ加速/回収）で分類する汎用部品で、
探索やルールベース側で「サーチがまだ残っているか」を判定するのに使える。
方策の特徴量とは独立に有用。
