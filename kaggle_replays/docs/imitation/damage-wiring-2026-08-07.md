# 打点計算への防壁配線の効果測定（2026-08-07）

> **状態: 有効** — **+10.8 Elo（95%CI [+1.3, +20.4]、p<0.05）**。
> 6シードの対応あり比較。効果は crustle 戦（+7.9pt、6/6シードで改善）に集中している。
> **B1 が示した「データ倍増 = +4.9 Elo」の2倍以上。**

## 1. 何を測ったか

`resolve_damage()` に `defender` と `damage_is_effect` を渡す配線（→ ロードマップ A10 段階1）の効果。
配線前は防壁が `can_ko` にしか反映されておらず、`best_attack_damage` は
「オーロンゲex が Crustle に 180 出せる」と言い続けていた。

marnie の教師データ 818,350局面のうち **7.3% で特徴量が変化**（すべて打点が減る方向、最大 -180）。

## 2. 測定設計 — 最初の設計は間違っていた

### 誤った1回目

配線後の3シードを、**B1 の対照群**（100%データ×3シード、Elo 214.2）と比べた。

```
+5.6 Elo  SE 1.9  t=2.97 (df=2)  臨界値 4.303  → 有意でない
```

**この比較は交絡していた。** 評価は `collect_pool` が実際に対戦を回すので、
**推論時にもエンコーダが走る**。B1 の評価は 08/06 21:11、A8/A10 がツリーに入ったのは 22:46。
つまり対照群だけ推論側が古いコードだった。

| | 学習特徴量 | 推論コード |
|---|---|---|
| B1 対照群 | 配線前 | **配線前** |
| 配線後（1回目） | 配線後 | 配線後 |

変更全体の A/B としては成立するが、**シードを足して検出力を上げるには対照群も同じコードで
回し直す必要がある**。

### 正しい2回目

対照群を**今のコードで**回し直した（旧特徴量 × seed 42,1,2,3,4,5）。
配線後も seed 3,4,5 を追加。**同一コード・特徴量だけが違う6ペア。**

Kaggle Notebook で計9本（同時実行上限が5なので2波に分けた）。1本あたり学習 約2.3時間＋評価。

**B1 の結論を補強する。**

| 打ち手 | 効果 | 根拠 |
|---|---:|---|
| 教師データを倍にする | +4.9 Elo | [data-scaling-2026-08-06.md](data-scaling-2026-08-06.md) の外挿 |

しかもリプレイ収集は上限 +12 Elo で頭打ちなのに対し、こちらはまだ他の誤りが残っている可能性がある。

## 6. 測定上の教訓

**① 対照群は「同じコードで」回し直す。**
特徴量を変える実験では、評価時に走る推論コードも変わる。過去の対照群を使い回すと交絡する。

**② 少数シードで相手別を読まない。**
今回、s42 単独では「alakazam +5.0pt / shirona_garchomp_ex −5.5pt」に見えたが、
6シードで均すと **−0.3pt / −1.5pt** だった。1セル n=200 では ±3.5pt 程度のばらつきがある。

**③ 2シードの一致を根拠にしない。**
「推論コードだけで 1.3〜1.4pt 下がる、2シードとも同じ向き」と一度報告したが、
3本目（s42）は逆向きだった。にげるコスト特徴で同じ失敗をしている
（→ [feature-retreat-prize-2026-08-04.md](feature-retreat-prize-2026-08-04.md)）。

**④ 対応ありの検定を使う。**
同一シード＝同じ初期値・同じバッチ順なので、対にすると SE が 4.5 → 3.7 Elo に下がる。
対応を無視すると同じデータでも有意にならない。
