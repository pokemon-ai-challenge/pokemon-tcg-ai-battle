# Pokémon TCG AI Battle Challenge

大学の研究室の4人で、**ポケモンカードゲームを自律的にプレイする AI** を開発しました。[Pokémon Trading Card Game AI Battle Challenge](https://ptcg-abc.pokemon.co.jp/) の第一ラウンド・シミュレーション部門に参加し、Kaggle 上で他チームの AI と対戦しました。

**最終 365位 / 6,807チーム — 上位約5.4%、銅メダル。**

AI 本体に加え、対戦記録から学習する仕組み、AI の判断を見返すビュアー、大量の対戦で改善を確かめる評価環境を開発しました。

第一ラウンドの開催体制（[公式サイト](https://ptcg-abc.pokemon.co.jp/)）：

- **主催・開催プラットフォーム：** Kaggle
- **共催：** 株式会社ポケモン（The Pokémon Company）、株式会社松尾研究所、HEROZ株式会社
- **開催協力：** Google、Google Cloud、NVIDIA

## 工夫したことと検証で分かったこと

**見えない相手の情報を仮定して、先を読む。** 相手の手札や山札は非公開です。ありうる中身を複数通り仮定し、それぞれで行動の結果をシミュレーションして、平均的に良い手を選ぶ仕組みを作りました。

**判断を見返せるようにして、改善につなげる。** 勝敗だけでは、どの判断に問題があったのか分かりません。対戦記録を集め、ビュアーで行動の候補や相手デッキの推定を確認できるようにしました。対戦記録は、上位プレイヤーの判断を学ぶための教師データにも使っています。

**多数の対戦で、変更の効果を確かめる。** 引くカードによって結果が変わるため、少数の勝敗だけでは改善を判断できません。AI の判断ロジックを固定して使用デッキを変更し、当時多かった相手を再現したローカル評価で約1万試合を実施。勝率が **70.1% → 76.2%（+6.1ポイント）** に上がることを確かめて採用しました。これは手元の評価環境での結果です。

相手デッキの予測を判断材料に加えることや、探索を深くすることなど、勝率の改善を確認できなかった施策もありました。検証結果を共有し、効果を確認できた方針に集中しました。[開発経緯と、うまくいかなかったこと](docs/development-story.md)

## AIの仕組み

最終エージェントは、当時多かった相手に有利なオーガポンデッキ（使用するカードの組み合わせ）と、3段構えの意思決定を組み合わせています。

```mermaid
flowchart TD
    A[盤面を観測する] --> B{今ターンに勝てる手順を探す}
    B -->|見つかった| Z[行動を選ぶ]
    B -->|見つからなかった| C[相手の手札や山札を仮定して先読みする]
    C -->|評価できた| D[評価の高い手を選ぶ]
    C -->|時間内に結論が出ない| E[学習モデルで手を選ぶ]
    D --> Z
    E --> Z
```

1. **今すぐ勝てる手を探す（確定リーサル探索）** — このターンに勝利できる行動の組み合わせを調べ、見つかれば優先します。
2. **先を読む（PIMC）** — 見えていない相手の手札や山札を複数通り仮定し、それぞれで数手先まで読んで行動を評価します。
3. **学習した判断を使う（模倣学習）** — 上位プレイヤーが実際に選んだ手を学習したモデルが、先読みでは時間内に結論が出ない場面を受け持ちます。

実装の入口は [`sample_submission/README.md`](sample_submission/README.md) です。対戦中の観測情報を受け取り、行動を返す `agent()` 関数から処理が始まります。

## チームでの進め方

研究室で「ハッカソンに出てみたい」「技術力を上げたい」という話がきっかけで参加しました。週2回の勉強会で機械学習の知識と実験結果を共有し、次に試す方針を決めました。

各自が別々の手法を試し、成果が出たものにチームで集中する進め方へ、途中で切り替えています。カードを印刷して実際にプレイすることも、デッキの強さや動きを理解するために役立ちました。
