# rule_agents — 手書きルールベース3種

環境上位のデッキ3つ（オーロンゲ／メガルカリオ／ジュラルドン）を、それぞれの勝ち筋に合わせて
人手で書いたルールベースエージェント。`league/` から対戦相手として使えるほか、
`diagnose.py` で「なぜ負けたか」を測りながら手を入れるための土台でもある。

```
rule_agents/
├── framework.py     エンジンとのやりとりだけを引き受ける共通部分（デッキ知識ゼロ）
├── grimmsnarl.py    オーロンゲ（マーニーのオーロンゲex）
├── lucario.py       メガルカリオex
├── archaludon.py    ジュラルドン／ブリジュラスex
├── diagnose.py      改良ループ用の計測スクリプト
└── decks/*.csv      各デッキ60枚
```

（`kaggle_replays/meta_analysis/archetype_decks/archaludon_ex/01.csv` と同じもの）。

## 判断の形

どの `SelectContext`（エンジンが何を選ばせているか）でも、やることは
「選択肢の配列から何個か選ぶ」で共通している。そこで **全選択肢に点数を付け、高い順に
`minCount`〜`maxCount` 個返す**という形に統一した。個数超過・重複・範囲外といった
ルール違反が構造的に起きない。

点数は `framework.py` の `S_*` 定数を帯として使う。1手打つたびにエンジンが選択を
やり直させるので、**点数の大小がそのまま1ターン内の行動順になる**。

| 帯 | 値 | 意味 |
|---|---|---|
| `S_MUST` | 90000 | 逃すと負ける／勝ちを逃す手 |
| `S_KEY` | 70000 | デッキの核（主軸への進化、ふしぎなアメ） |
| `S_TOOL` | 60000 | 道具付け |
| `S_DEVELOP` | 50000 | たねポケモンをベンチに出す |
| `S_SEARCH` | 40000 | サーチ・ドローのアイテム |
| `S_ENERGY` | 30000 | エネルギー付け |
| `S_RETREAT` | 20000 | にげる |
| `S_REFRESH` | 15000 | 手札を丸ごと引き直すサポート（やることを済ませてから） |
| `S_ATTACK` | 10000 | 攻撃（＝ターン終了） |
| `S_END` | 100 | 何もせずターン終了 |
| `SKIP` | -1 | 選ばない |

「リーリエの決意」のような**手札を山に戻して引き直すサポートを `S_REFRESH` に置いてある
のは意図的**。エネルギーを貼り、進化させ、アイテムを使い切ってから最後に手札を入れ替える
という順番が、点数の大小だけで自然に出る。

デッキ固有の判断は `Strategy` のフック（`play_score` / `attach_score` / `evolve_score` /
`attack_score` / `want_in_hand` など）を上書きして書く。`framework.py` はカードIDを
一切知らない。

## 使い方

### 対戦（勝率を測る）

```bash
cd sample_submission
python3 ../league/run_league.py \
  --agent-a grimmsnarl_rule --agent-b lucario_rule \
  --deck-a opponents/rule_agents/decks/marnie_grimmsnarl_ex.csv \
  --deck-b opponents/rule_agents/decks/mega_lucario_ex.csv \
  --games 300 --workers 8
```

`--deck-a/--deck-b` には必ず対応するCSVを渡すこと。エージェントは自分のデッキ内訳を
前提に山札の残りを推定しているため、実際に使うデッキと食い違うと判断がずれる。

### 計測（なぜ負けたかを見る）

```bash
cd sample_submission
python3 ../opponents/rule_agents/diagnose.py --round-robin --games 100
```

勝率に加えて、主役が場に出たターン、最初にワザを撃てたターン、使ったワザの内訳、
「ワザを撃てるのに撃たずに終えた回数」、決着理由（サイド／山札切れ／バトル場が空）を出す。

未対応の `SelectContext` に落ちたときは環境変数で警告を出せる。

```bash
RULE_AGENT_DEBUG=1 python3 ../opponents/rule_agents/diagnose.py --a grimmsnarl_rule --b lucario_rule --games 50
```

## 現在の勝率（総当たり300試合／組、先攻後攻は半々）

| | vs オーロンゲ | vs メガルカリオ | vs ジュラルドン |
|---|---|---|---|
| **オーロンゲ** | — | 0.457 | 0.530 |
| **メガルカリオ** | 0.543 | — | 0.520 |
| **ジュラルドン** | 0.470 | 0.480 | — |

エラー0件、未対応の選択文脈も0件。3すくみに近い形で、どの組み合わせも0.46〜0.54に収まっている。

残っている弱点は2つ。

- **メガルカリオが最後まで場に出ない試合が13〜16%ある。** リオルが3枚しかないうえ、
  倒されるとサイドを3枚渡すので、土台が尽きると立て直せない。
- **ジュラルドンは負けた試合の約半分が「バトル場が空」。** ベンチに出せるたねが
  ジュラルドン4枚とジーランス1枚しかない構造的な弱さで、展開の優先度を上げても
  完全には消えていない。

## 改良ループで実際に直したこと

計測 → 原因を1つ特定 → 直す → 再計測、を回した記録。数字はすべて `diagnose.py` の出力。

### 1. バトル場が空になって負ける（最大の敗因だった）

ジュラルドン同型60試合のうち37試合がこの負け方だった。自分の2ターン目時点でベンチが
平均1.2体、うち14試合はベンチが空。「ベンチを埋めるとボスの指令で弱いところを
引きずり出される」と考えて展開を絞りすぎていたのが原因。

盤面のポケモンが2体以下ならベンチ展開を最優先にする規則を3デッキ全部に入れた結果、
この負け方はジュラルドン同型で 37 → 14 試合、オーロンゲ戦で 25 → 13 試合に減った。

### 2. 前のポケモンにエネルギーが乗らず、11ターン目まで殴れなかった

ジュラルドンの最初の攻撃が平均11.1ターン目（同型では12.3ターン目）だった。1試合を
1手ずつ表示して追うと、原因は2つ:

- エネルギーを**ベンチの**ジュラルドンから貼っていた（「進化前から積んでおく」つもりで
  ベンチ側の点数を高くしていた）。前がエネルギー0のまま放置される。
- 進化させるジュラルドンを「バトル場にいるかどうか」だけで選んでいた。エネルギー0の
  ジュラルドンがブリジュラスexになるので、鋼3個が揃うまで何ターンもかかる。

前から貼る・エネルギーが多い方を進化させる、に直して、最初の攻撃は 11.1 → 6.8 ターン目、
同型では 12.3 → 7.1 ターン目になった。勝率も対オーロンゲで 0.37 → 0.47。

### 3. エネルギー0のポケモンが前に出ると、盤面が完全に止まる

オーロンゲでマンキーがバトル場に出た試合を追うと、5ターン以上何もできていなかった。
にげるにはエネルギーが要るので、エネルギー0だと**ワザも撃てず、にげることもできない**。

「前のポケモンがワザも撃てず逃げることもできないなら、逃げるためだけにエネルギーを
1枚貼る」を3デッキ共通の規則として入れた（`framework.retreat_blocked`）。
「ワザの選択肢が無いままターンを終えた回数」が1試合あたり 2.0〜2.9 → 1.4〜1.8 に減り、
平均試合時間も短くなった。

### 4. オーラジャブ（130）をメガブレイブ（270）より優先していた

メガルカリオの使用比が オーラジャブ 2.3 : メガブレイブ 1。本来は交互に撃つのが素の形。
オーラジャブに付けていた「トラッシュから闘エネを回収できる」加点が +700 で、
打点差140をひっくり返していた。+60 に下げた。

### 5. パンクアップの5枚を1体に集めていた

オーロンゲexの特性は基本悪エネルギーを最大5枚持ってこられるが、ワザに必要なのは2枚。
残り3枚が遊んでいた。控えのベロバー／ギモーに配るよう点数を組み直した
（控えが進化すれば、そのエネルギーがそのまま次のアタッカーになる）。

### 6. 先攻/後攻の判断が逆だった（オーロンゲ）

「先攻はサポートを使えないので、初動が全部サポートのオーロンゲは後攻が良い」と考えて
後攻にしていた。メガルカリオ相手に200試合ずつ測ると逆で、後攻 0.39〜0.40 に対して
先攻 0.44〜0.46。オーロンゲexが場に出るターンも 9.9 → 8.9 と1ターン早くなる。
2段階進化を組むのに使える手番が1回増える方が、サポート1枚を我慢する損より大きかった。

### 直したが効果が無かったもの

**ユキメノコ（凍てつく霧）を出す条件**。この特性は特性を持つポケモン**全員**にダメカンを
乗せるので、メガルカリオex（特性なし）相手だと、こちらのオーロンゲexとマンキーだけが
削られる。そこで「相手の特性持ちの方が多いときだけ出す」に変えたが、300試合での勝率は
0.387 → 0.390 でほぼ変わらなかった（そもそもユキメノコが立つ試合が少ない）。
理屈は正しいので採用しているが、勝率への寄与は測れていない。
