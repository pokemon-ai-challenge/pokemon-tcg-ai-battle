# main.py の解説

このドキュメントは `main.py` の全体像を、コードを読んだことがない人でも理解できるよう説明します。

---

## 一言で言うと

> **「毎手番、使える手を全部試してランダムに最後まで対戦させ、一番勝率が高かった手を選ぶ AI」**

---

## 全体の流れ

```
対戦エンジン
  ↓ obs_dict（盤面情報）
agent(obs_dict)
  ├─ 初回のみ → deck.csv を読んでデッキ 60 枚を返す
  └─ 通常ターン
       ↓
       盤面情報を整理
       ↓
       Flat Monte Carlo Search（時間内にできる限り試行）
         ├─ 候補手 A → ランダムに最後まで対戦 × N 回 → 平均勝率 Q(A)
         ├─ 候補手 B → ランダムに最後まで対戦 × N 回 → 平均勝率 Q(B)
         └─ ...
       ↓
       Q が最大の手を返す
       ↓
       （失敗時）ルールベースのフォールバック
```

---

## 大きく 5 つのブロックに分かれています

### 1. カード辞書の読み込み（起動時 1 度だけ）

```
_CARD_DB  : カード ID → カード情報（名前・HP・タイプなど）
_ATTACK_DB: 攻撃 ID  → 攻撃情報（名前・ダメージ・必要エネルギー）
```

ゲームエンジンが提供する `all_card_data()` / `all_attack()` から取得し、
手札や選択肢に出てくるカード ID を即座に「名前・強さ」に変換できるようにしています。

---

### 2. 評価関数 `evaluate()`

盤面が「自分にとってどれだけ有利か」を数値化します。

| 指標 | 比重 | 意味 |
|------|------|------|
| サイドカード残枚数差 | 60% | 残り少ない方が勝利に近い（最重要） |
| **相手ポケモンのダメカン進捗差** | **18%** | **特性で乗せたダメカンの価値。ex ポケモン（サイド 2 枚）に乗ると高評価** |
| バトルポケモンの HP 比率差 | 10% | 自分のポケモンが元気 = 有利 |
| 進化段階ボーナス | 8% | Dragapult ex / Blaziken ex が場にいると + |
| エネルギー数 | 2% | バトルポケモンにエネルギーが乗っている = 攻撃準備 OK |
| ベンチ展開差 | 2% | ベンチが多い方が次の展開に余裕がある |

返す値は **-1.0（絶対負け）〜 +1.0（絶対勝ち）** の範囲。

> **特性が効くカギ:** 「相手ポケモンのダメカン進捗差」を報酬に入れたことで、
> Munkidori や Chi-Yu の特性で相手にダメカンを乗せるほど評価値が上がります。
> その結果、後述の Monte Carlo 探索が **「特性を使う手」を自然に高く評価する**ようになります。
> ダメカン進捗は「きぜつまでの近さ × そのポケモンを倒したときに取れるサイド枚数」で計算するので、
> **ex ポケモン（サイド 2 枚）を削る手が優先**されます。

### 3. Flat Monte Carlo Search（メインの探索）

AI の核心部分です。

#### やっていること

```
1 手の制限時間（最大 10 秒）内に以下を繰り返す:
  1. 今取れる手を候補としてリストアップ（最大 12 個）
  2. 候補手を 1 つ選ぶ（順番に回す）
  3. その手を打った後、両プレイヤーがランダムに最大 30 手打つ
  4. 終局 or 深さ制限に達したら evaluate() で盤面評価
  5. 候補手の平均評価値 Q を更新

最終的に Q が最大の候補手を返す
```

#### 時間の使い方（動的時間マネージャ）

ゲーム全体の制限時間は **10 分（600 秒）**。これを「1 ゲームで使ってよい総計算時間」とみなし、
**その範囲内で 1 手にできる限り時間をかけて精度を上げます。**

単純に「1 手 N 秒」固定にすると危険です。MC 探索は MAIN だけでなく複数候補のある選択
ほぼ全てで走り、1 ゲームで **33〜120 回** 呼ばれるからです（実測）。固定 8 秒 × 120 回 = 960 秒で
簡単に上限を超えてしまいます。

そこで `_decision_budget()` が **1 手の予算を動的に決めます**。

```
残り時間 = GAME_TIME_CAP(540秒) − これまでの累積使用時間
1手の予算 = clamp(残り時間 ÷ 40, 下限1秒, 上限10秒)
          ただし残り時間を絶対に超えない
```

- **序盤〜中盤**: 1 手に上限の **10 秒**（旧 3 秒の 3.3 倍）かけて精度を最大化
- **終盤**: 残り時間に応じて自動的に予算を絞り、手が枯渇しない
- **数学的保証**: `予算 ≤ 残り時間 ÷ 40 < 残り時間` なので、
  何手かかっても **累積が 540 秒を超えない**（= タイムアウトしない）

| ゲーム長 | AI の総使用時間 | 1 手目 | 最終手 |
|---------|----------------|--------|--------|
| 33 手（短い） | 約 293 秒 | 10 秒 | 6.3 秒 |
| 70 手（接戦） | 約 443 秒 | 10 秒 | 2.5 秒 |
| 122 手（長期戦） | 約 517 秒 | 10 秒 | 1.0 秒 |
| 200 手（極端） | 540 秒ちょうど | 10 秒 | 0 秒 |

600 秒の制限に対し常に 60 秒以上のマージンを残します。

#### なぜランダムな対戦シミュレーションが有効なのか

- ポケモンカードゲームは手番や運要素があり、全探索は不可能
- ランダムロールアウトを多数繰り返すと、「統計的に有利な手」が浮かび上がる
- これは **モンテカルロ法**（大量の乱数試行で答えを近似する手法）の応用

#### 強化学習との対応

| RL の用語 | この実装での対応 |
|-----------|----------------|
| 状態 S | `Observation`（盤面・手札・ログ） |
| 行動 A | `list[int]`（選択肢インデックス） |
| 報酬 R | +1 勝利 / -1 敗北 / 途中 = 評価関数 |
| Q(s, a) | ロールアウトの平均報酬（モンテカルロ推定） |
| 方策 π | argmax Q(s, a) を返す |

### 4. ヒューリスティック（ルールベースのフォールバック）

MC 探索が失敗したとき（例外発生・時間切れ）に使うバックアップです。  
「こういう状況ではこの手を優先する」という人間の知識をコードで表現しています。

#### メインフェーズの優先順位

```
1. 進化できるなら進化する
     └─ Dragapult ex > Drakloak > Blaziken ex を優先
2. 特性（Ability）を使う  ★攻撃より先
     └─ Munkidori > Chi-Yu > Fezandipiti ex を優先
     └─ ダメカンを先に乗せてから攻撃 → 確定きぜつを狙う（先積み戦術）
3. エネルギーを付けていないなら付ける
     └─ Dragapult ex のいるポケモンに優先付け
4. 攻撃できるなら攻撃する
     └─ 相手をきぜつさせられる攻撃を最優先
5. 手札からカードを使う
6. ターン終了
```

> **特性を「攻撃の前」に置いているのが重要なポイント**です。
> 先に Munkidori などでダメカンを乗せておけば、その後の攻撃で「あと一歩で倒せない」相手を
> 確実にきぜつさせられます。

#### 特性を使ったときの「どこに乗せるか」

特性を発動すると「ダメカンをどの相手ポケモンに乗せるか」を選ぶ場面（DAMAGE_COUNTER）になります。
ここでは次の優先順位で**狙うポケモンを選びます**。

```
1. このダメカンで「きぜつ」させられる相手ポケモン（特に ex はサイド 2 枚なので最優先）
2. すでにダメカンが乗っている ex ポケモン（積み増して仕留めにいく）
3. それ以外は HP が低い相手ポケモン
```

これにより、ただ特性を使うだけでなく **「倒すと一番得なポケモンを的確に削る」** 動きになります。

#### セットアップ時の選択

**バトルポケモン（Active）の選択:**
- Dreepy（Dragapult の進化元、HP が低い）を壁役にして場に出す
- Dreepy がいなければ HP が最も低いポケモン（メインアタッカーを温存）

**ベンチポケモンの選択:**
- できるだけ多くのポケモンをベンチに出す
- Dreepy → Torchic → Munkidori の優先順位（特性持ちも早めに並べる）

#### その他の選択場面

| 場面 | 方針 |
|------|------|
| 回復・ダメカン除去 | HP が最も減っている自分のポケモンを回復 |
| 捨て札 | 進化元（Dreepy/Torchic）や特性持ちを温存し、エネ・グッズから捨てる |
| 手札に加える | Dragapult ex / Drakloak / Munkidori を優先回収 |
| はい/いいえ・コイン | 基本「はい」「表」を選ぶ（効果を発動する方向） |

### 5. 相手デッキの予測

`search_begin()` API を使うには、相手の非公開情報（手札・デッキ・サイド）を入力する必要があります。  
完全には分からないので、以下のルールで予測しています。

1. **対戦中に相手が公開したカード**（ログに記録済み）を優先使用
2. **残りは自分のデッキで補完**（相手も似たようなデッキを使うと仮定）
3. **不足分はデッキカードを繰り返す**（必要枚数を必ず確保）

この予測が不正確でも、ランダムロールアウトの試行回数でカバーしています。

## 特性まわりの対応状況（このバージョンで強化）

| 項目 | 対応 |
|------|------|
| 特性をそもそも使うか | ✅ MAIN で攻撃より先に発動（Munkidori > Chi-Yu > Fezandipiti ex） |
| ダメカンを誰に乗せるか | ✅ きぜつ可能・ex 優先でターゲティング |
| 特性の価値を探索が理解するか | ✅ 評価関数にダメカン進捗（18%）を追加し MC 探索が学習 |
| ダメカン個数選択 | ✅ 最大個数を選ぶ |

> 自己対戦 1 ゲームの計測で、MAIN フェーズの特性選択が **29 回**、
> ダメカン配置の場面が **12 回** 発生することを確認済み（`diag_ability.py`）。
