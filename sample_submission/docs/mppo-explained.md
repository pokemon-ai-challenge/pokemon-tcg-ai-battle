# Maskable PPO ドラパルトAI — やさしい解説

> このファイルは、**プログラミングをしたことがない人**にも「何を作ったのか」「なぜそう作ったのか」が
> 伝わるように書いた説明書です。専門用語にはそのつど短い言いかえを付けます。
> 技術的な詳細（設計の正式な仕様）は同じフォルダの `mppo-spec.md` にあります。

---

## 1. ひとことで言うと

**ポケモンカードを、AIが「自分で何百回も対戦しながら」少しずつ強くなるように学習させた**ものです。

人間がルールを全部書く（「この場面ではこう動け」と命令する）のではなく、
AIに「勝てば良い・負ければ悪い」とだけ教えて、**良い動きを自分で見つけさせます**。
この「やってみて、結果から学ぶ」やり方を **強化学習（きょうかがくしゅう）** と呼びます。

---

## 2. 強化学習を、ゲームの上達でたとえる

あなたが新しい対戦ゲームを始めたところを想像してください。

1. 最初はルールもよく分からず、てきとうに動く（**ランダム**）。
2. 何回も対戦するうちに「この動きをすると勝ちやすい」と体で覚える。
3. 勝った試合の動きは増やし、負けた試合の動きは減らす。

AIもまったく同じことをします。違うのは、**人間なら数百試合かかる経験を、コンピュータは何万試合も高速にこなせる**ことです。

- 「勝ち＝ごほうび(+1)」「負け＝ばつ(-1)」を **報酬（ほうしゅう）** と呼びます。
- 「どの場面でどう動くか」の方針を **方策（ほうさく / ポリシー）** と呼びます。AIの“頭脳”です。
- 方策を少しずつ良い方向に書き換えていくアルゴリズムが **PPO** です。

---

## 3. 「Maskable（マスカブル）」とは？

ポケカでは、場面ごとに「選べる行動」が変わります。
例えばエネルギーが無ければ「ワザを使う」は選べません。

**Maskable PPO の "マスク" は「いま選べない行動にフタをする」仕組み**です。
AIが反則の手（ルール上できない手）を選んでしまわないよう、毎回
「この手はOK／この手はダメ」という一覧（**マスク**）を渡します。
こうすると、AIは**必ず合法な手の中だけ**から選ぶので、対戦が壊れません。

> たとえ：将棋でAIに「動かせる駒だけ光らせて見せる」ようなものです。光っていない手は選べません。

---

## 4. ポケカをAIに学習させるのが難しい理由（作る前から分かっていたこと）

ポケカは、よくAIの練習に使われるゲーム（オセロやブロック崩し）より、ずっと複雑です。

1. **場面ごとに「選択肢の意味」も「個数」も変わる**
   ふつうのゲームAIは「上・下・左・右」など決まった行動から選びます。
   ポケカは「手札のどれを使うか」「どのポケモンに付けるか」「何枚捨てるか」など、
   場面ごとに選択肢がバラバラ。これをAIが扱える形に**そろえる**必要がありました。

2. **盤面の情報がとても多い**
   自分と相手のポケモン、エネルギー、手札、サイド、特殊状態……。
   これを**決まった長さの数字の列**に翻訳しないと、AIは読めません（この翻訳機を作りました。長さは **2602個の数字**）。

3. **勝ち負けが分かるのは最後だけ**
   「この1手が良かったか」は、その場では分かりません。試合が終わって初めて勝敗が出ます。
   だから学習はゆっくりで、**たくさんの試合数**が要ります。

4. **対戦相手が必要**
   一人では練習できません。最初は「でたらめに動く相手」、慣れてきたら「自分のコピー」と戦わせます。

5. **本番（Kaggle提出）で動く保証**
   提出先のコンピュータに、学習用の重いソフト（PyTorch）が入っているか分かりません。

これらは**作る前から想定していた課題**です。次の章で、どう解いたかを説明します。

## 5. 解決のしくみ（全体像）

```
        ┌─────────────────── 学習（自分のPCで何万試合）───────────────────┐
        │                                                                  │
   [対戦エンジン] ──盤面──▶ [翻訳機] ──2602個の数字──▶ [AIの頭脳] ──手──▶ │
    cg(ゲーム本体)          features.py                MaskablePPO          │
        ▲                       │                          │               │
        │                  [マスク：選べる手だけ]          │               │
        └────────── 相手（でたらめ／自分のコピー／MC）◀────┘               │
                                                                           │
        勝敗(+1/-1) を見て「頭脳」を少しずつ修正 ──────────────────────────┘

        ┌─────────────────── 提出（Kaggleの本番）──────────────────────┐
        │  学習で得た「頭脳の数値」だけを取り出して policy.npz に保存     │
        │  本番では numpy（軽い計算ライブラリ）だけで同じ判断を再現        │
        └───────────────────────────────────────────────────────────────┘
```

### 工夫1：選択を「1つずつ選ぶ」形に分解
「最大2枚捨てる」のような複数選択は、AIには扱いにくいです。
そこで **「1つ選ぶ→もう1つ選ぶ→もう終わり(STOP)」** と、1手ずつに分けました。
これで、どんな場面も**同じ仕組み**で扱えます。

### 工夫2：盤面を数字に翻訳する（features.py）
ポケモンのHP・エネルギー数・進化段階、サイドの残り、いま何を選ぶ場面か……を
すべて0〜1くらいの数字に直し、決まった長さ（2602個）に並べます。
**この翻訳機は「学習用」と「本番用」で同じものを使います**（ずれると学習が無駄になるため）。

### 工夫3：相手を段階的に強くする（カリキュラム）
- 序盤：**でたらめな相手**（ランダム）で基礎を作る
- 中盤以降：**自分の少し前のコピー**（自己対戦）や、**ルールベースの強めの相手（MC）**と戦う

弱い相手から強い相手へ、というのは人間の練習と同じ考え方です。

## 6. 部品（ファイル）の役割いちらん

| ファイル | これは何をする？ |
|---------|------------------|
| `main.py` | **提出する本体**。本番で「次の一手」を返す。中身は軽いnumpy計算だけ。 |
| `deck.csv` | 使う60枚のデッキ（ドラパルトex 軸）。 |
| `tcg_rl/features.py` | **翻訳機**。盤面→2602個の数字＋「選べる手の一覧(マスク)」。学習と本番で共有。 |
| `tcg_rl/mlp_numpy.py` | 本番用の**頭脳の計算**（numpyだけ）。学習結果(policy.npz)を読んで一手を決める。 |
| `tcg_rl/env.py` | **練習場**。ゲーム本体を強化学習が使える形に包む。 |
| `tcg_rl/opponents.py` | **対戦相手**（でたらめ／自己対戦／MC）の用意。 |
| `tcg_rl/mc_agent.py` | **ルールベースの強めAI**（モンテカルロ＋手作りルール）。相手役＆評価関数の改良対象。 |
| `train_ppo.py` | **学習を回す司令塔**。相手を切り替え、定期的に強さを測り、結果を保存。 |
| `export_policy.py` | 学習済みの頭脳を、本番用の軽い形(policy.npz)に**書き出す**。 |
| `make_submission.py` | 提出ファイル(submission.tar.gz)を**正しく梱包**する。 |
| `policy.npz` | **学習でできた頭脳の数値**。これが“強さ”の本体。 |
| `viewer/`（別フォルダ） | **対戦をブラウザで観戦・自分でプレイ**できるおまけツール。提出とは無関係。 |

## 7. 使い方（コマンド）

`sample_submission` フォルダで実行します。

```powershell
# 1) 学習する（時間がかかる。途中で勝率が表示される）
python train_ppo.py --opponent curriculum --use-mc --timesteps 200000

#   よく使う追加オプション：
#   --mc-budget 0.3     相手のルールベースAI(MC)に「0.3秒だけ先読み」させて強くする
#   --turn-penalty 0.01 ダラダラ引き延ばす動きに小さな減点（さっさと勝ちにいく）
#   --checkpoint-freq 20000  途中でも policy.npz を保存し続ける（中断しても最新が残る）

# 2) （学習は最後に自動で policy.npz を書き出します。手動でやり直す場合）
python export_policy.py --model models/mppo_dragapult.zip --out policy.npz

# 3) 本番と同じ形で動作確認（合法手を最後まで返せるか）
python local_test_advanced.py --opponent random --games 20

# 4) 提出ファイルを作る
python make_submission.py    # submission.tar.gz ができる

# 5) （おまけ）対戦をブラウザで観戦・自分でプレイする
python ../viewer/server.py   # 起動後 http://localhost:8000 を開く
```

## 8. 本番で「numpyだけ」で動かす理由

学習には PyTorch という重いソフトを使いますが、**提出先で動く保証がありません**。
そこで、学習で得た“頭脳の数値”だけを取り出し、**numpy（とても軽い計算ライブラリ）で同じ計算を再現**します。
実際に、PyTorchの答えと numpy の答えが**ほぼ完全に一致**することを確認済みです（差は0.0000000005ほど）。
これで、提出先の環境に左右されず、確実に動きます。

## 9. 作る前から分かっていた課題（再掲・要点）

- **学習が遅い／不安定になりやすい**：選択肢が膨大で、勝敗が最後にしか分からないため。
- **翻訳機がずれると台無し**：学習用と本番用で同じ翻訳を使う必要がある。
- **本番環境が不明**：重いソフトに頼らない作りが必要。
- **対戦相手の質が学習の質を決める**：弱い相手だけだと、強くはなれない。

---

## 10. 作ってみて分かった課題（今後の課題）

実装と動作確認を通じて、新たに分かったことです。

1. **「同時に1試合しか動かせない」制約があった**
   ゲーム本体の都合で、1つのプログラムの中で**対戦を2つ同時に動かせない**ことが判明。
   学習中に「強さを測る別対戦」を始めると、進行中の対戦が壊れる不具合が出ました。
   → 対戦が壊れたら**その試合だけ打ち切って作り直す**仕組みを入れて解決。
   ただし、**学習を速くするための並列化（複数試合を同時進行）が難しい**という宿題が残っています。
   将来は「別プロセスで複数同時」に挑戦する余地があります。

2. **学習に時間がかかる**
   短時間（8000試合ぶん）でも「でたらめ相手に勝率0.4→0.8」まで伸びることは確認できました。
   しかし**本当に強くする**には、もっと長い学習（何十万〜何百万試合ぶん）とパラメータ調整が必要です。
   いまのGPUなし環境では時間がかかります。

3. **「盤面の翻訳」がまだ素朴**
   いまは基本的な情報（HP・エネルギー・進化段階など）だけを数字にしています。
   「特定カードの効果」や「相手の残り枚数の細かい読み」までは入れていません。
   ここを丁寧にするほど、AIは賢くなれる見込みです（ただし作りこみが必要）。

4. **複数枚を選ぶ場面の戦略はこれから**
   「1つずつ選ぶ」分解はうまく動きますが、**枚数の多い選択での最適化**はまだ伸びしろがあります。

5. **ルールベースAI(MC)の評価関数に改善余地**
   相手役にも使うルールベースAIは、いまの手作りルールで**でたらめ相手に約68%勝**です。
   評価関数（盤面の良し悪しを点数化する部分）を改良すれば、相手役としても、単体の強さとしても上がります。
   候補：「次のターンも攻撃を続けられるか」「ボス・入れ替えなどの妨害札が手元にあるか」「サイドの取り方(2-2-2)」など。

6. **本番環境の最終確認はこれから**
   numpyだけで動く設計なので問題は出にくいはずですが、**実際の提出での時間・メモリ制限**は提出してみないと最終確認できません。

## 11. まとめ

- 「勝てば良い・負ければ悪い」だけを頼りに、AIが**自分で対戦して強くなる**仕組みを作りました。
- ポケカ特有の難しさ（選択肢がバラバラ・情報が多い・勝敗が最後だけ）を、
  **1手ずつの分解**・**盤面の翻訳機**・**選べる手だけにフタ(マスク)**・**段階的な対戦相手**で解決しました。
- 本番は**軽いnumpy計算**だけで動き、学習結果(`policy.npz`)を読み込んで一手を返します。
- 仕組みは完成し、学習で**実際に強くなる**ことを確認済み。
  残るのは「**もっと長く学習する**」「**翻訳機と評価関数を作りこむ**」「**並列化で高速化**」という伸びしろです。

## 12. 最近の更新（現在の状況）

別マシンでの作業を取り込み、いまは次の状態です（ローカルとリモートは同期済み）。

1. **本番(Kaggle)で確実に動くよう修正**
   Kaggle はプログラムを特殊な方法で起動するため、「自分の置き場所」を見失って落ちることがありました。
   置き場所が分からないときは決まったフォルダを使う、という安全策を入れて解決しました。

2. **「ダラダラ引き延ばす動き」を減らせるようにした（任意のオプション）**
   勝ちを急がず時間を稼ぐような消極的プレイに、**小さな減点**を与えられるようにしました
   （`--turn-penalty`。使うかどうかは選べます）。

3. **練習相手のルールベースAIを「少し先読み」させられるようにした**
   `--mc-budget 0.3` のように指定すると、相手AIが0.3秒だけ先を読んで強くなります。
   **強い相手と練習するほど自分も強くなりやすい**、という狙いです。

4. **学習を途中でやめても、最新の成果が残るようにした**
   一定回数ごとに `policy.npz`（頭脳）を自動保存（`--checkpoint-freq`）。
   長い学習を安心して回せます。

5. **対戦を「見える化」するビューアを追加（おまけ）**
   ブラウザで **AI同士の対戦を観戦**したり、**自分でAIと対戦**したりできるツール（`viewer/`）が入りました。
   これは提出物とは無関係ですが、**AIがどう打っているかを目で確認**でき、評価関数の改良に役立ちます。
   起動：`python viewer/server.py` → `http://localhost:8000`

> まだ「本気の長時間学習」や「評価関数の作り込み」はこれからです。道具立て（学習・観戦・保存）は整いました。
