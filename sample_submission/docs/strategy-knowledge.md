# 戦略知識ベース

このファイルは AI が実装・テストを通じて得た「なぜそう書いたか」を蓄積するドキュメントです。

**読む人：**
- 次のAIセッション（コードの意図を理解するために読む）
- 人間（判断が正しいか検証・修正するために読む）

**書く人（タイミング）：**
- 戦術評価AI → 方針を決定したとき
- コーディングAI → 非自明な実装判断をしたとき
- ベンチマーク分析AI → テスト結果で勝率変化を確認したとき
- デバッグAI → 判断が間違っていたことが判明したとき
- 提出後改善AI → Kaggleログから新知見を得たとき

## エントリの書き方

```markdown
### [ID] タイトル
- **適用範囲:** COMMON（全デッキ）/ LUCARIO（メガルカリオex系）/ など
- **結論:** 何をすべきか（1文で）
- **根拠:** なぜそうするか
- **例外:** この結論が当てはまらないケース
- **状態:** 仮説 / 検証済み / 否定済み
- **検証:** テスト結果があれば記載（勝率変化など）
- **実装:** 該当するコード箇所
```

### [META-007] 相手デッキ推定システムの全体設計
- **適用範囲:** META（`src/knowledge/opponent_model.py` 全体）
- **結論:** 盤面の公開カード ID を蓄積 → 重み付きスコア（1/N 法）でアーキタイプを推定 → ボスの指令ターゲットを自動選択。
- **アルゴリズム要点:**
  - 公開カードがN個のデッキに採用されている場合、各デッキに 1/N の重みを加算
  - 正規化スコアが MIN_CONFIDENCE(0.3) 以上のアーキタイプを採用
  - ARCH_BOSS_TARGETS でアーキタイプ別の優先ターゲットを返す
- **利用箇所:** `target_policy.py:choose_switch()` でボス対象を決定
- **未接続の拡張:** `ex_immune.py`（EX 無効化検出）/ `MatchupPolicy`（ベンチ上限など）は設計済みだが未接続
- **全詳細:** `docs/opponent_model.md`（フロー図・ターゲットテーブル・ベンチマーク結果・拡張手順）
- **状態:** 検証済み（ボスターゲット機能は全 10 デッキで動作確認済み）

## 探索API（SEARCH）

### [SEARCH-001] search_begin の相手情報推定戦略（Phase 4 設計方針）
- **適用範囲:** COMMON（全フェーズで参照）
- **結論:** 相手の非公開情報は「公開済み情報の逆算 + メタデッキアーキタイプ推定」で最善推定する
- **根拠:**
  - `search_begin` には相手のデッキ・プライズ・手札・バトル場（伏せの場合）を渡す必要がある
  - これらは実際には非公開情報だが、推定なしでは探索が不可能
  - 間違った推定でも「完全ランダムな仮定」より「アーキタイプ傾向を反映した仮定」の方が探索の質が高い
- **推定アルゴリズム（保守的設計）:**
  ```
  1. 相手デッキの推定:
     a. estimate_deck_candidates(公開済みカードID) → 最も確率の高いアーキタイプを特定
     b. アーキタイプのレシピ60枚を展開する
     c. 相手の公開済みカード（バトル場・ベンチ・手札から使用・トラッシュ）を除去
     d. 残りカード数を state.players[opp].deckCount に合わせて調整（多ければ切り詰め、少なければ基本エネルギーで補充）
  
  2. 相手プライズの推定:
     a. 相手の推定デッキ残りカードからランダムに len(opp.prize) 枚取り出す
  
  3. 相手手札の推定:
     a. デッキ・プライズに割り当てた残りをそのまま手札候補とする
     b. opp.handCount 枚をそこから割り当てる
  
  4. 相手バトル場（伏せ）の推定:
     a. opp.active[0] が None の場合のみ必要
     b. アーキタイプの active_priority 先頭カードを使う（その ID の Basic ポケモン）
  
  5. 自分デッキの推定:
     a. 自分の完全なデッキレシピ（read_deck_csv() の60枚）から既知の使用カードを差し引く
     b. 自分のトラッシュ・バトル場・ベンチに出ているカードが「使用済み」
     c. 手札は判明済みなので除外しない（deck の引数には残りデッキのみ）
  
  6. 自分プライズの推定:
     a. 残り推定カード中から state.players[my].prize 枚をランダム割り当て
  ```
- **フォールバック条件（探索を使わない場合）:**
  - ゲーム開始3ターン以内で相手カードが1枚も公開されていない場合
  - 推定デッキ枚数が実際の deckCount と 5 枚以上ずれる場合
  - search_begin が例外を投げた場合（ValueError）
  - これらの場合は evaluator ベースの通常選択に fallback する
- **推定が外れた場合の影響:**
  - 深さ4〜8アクションの探索では、序盤ターンの外れより「終端状態の評価精度」の方が重要
  - 保守的仮定（相手の手札に Boss's Orders があると仮定）は探索が悲観的すぎる結果を出す可能性があるが、安全側に倒す
- **状態:** 設計完了（実装待ち）
- **実装:** `src/decision/search_policy.py`
