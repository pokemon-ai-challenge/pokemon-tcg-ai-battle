# ML エージェント方針メモ(自分用)

作成: 2026-07-20
状態: 方針検討段階(実装未着手)

Kaggle 上位リプレイを使った機械学習ベースのエージェントを作るための個人方針メモ。
他メンバーが編集中のファイル(rule_based 等)には手を入れず、config 切り替えで共存させる。

---

## 基本方針

- **上位リプレイの模倣(Behavior Cloning)を土台にする。**
  データパイプラインは `kaggle_replays/` に既にある
  (上位エピソード取得 → `(observation, action)` ペア抽出 → 順位による重み付け)。
  ただし模倣の上限は「真似た相手の強さ」なので、これは土台であって最終形ではない。
- **デッキは Kaggle 上位を真似る。**
  プレイングの学習データとデッキが一致するので模倣学習と相性が良い。
- **ゼロからの自己対戦はやらない。**
  弱い初期構築のまま自己対戦すると変な癖を学習するリスクがある。
  盤面評価AI(バリュー関数)を先に作る。これは自己対戦なしで作れる(下記)。
- **既存コードと混ぜない。**
  新モジュールは `ptcg_ai/learning/` 配下、設定は `configs/ml_policy.json` のような
  新規 config で切り替える(`PTCG_AI_CONFIG` 環境変数 / `core/config.py` の仕組みに乗る)。

## 既に揃っている部品

| 部品 | 場所 | 状態 |
|------|------|------|
| リプレイ取得・学習データ抽出 | `kaggle_replays/` | 実装済み。順位重み付きの JSONL 出力まで |
| 相手デッキ推定(ML/NB/hybrid) | `ptcg_ai/opponent_modeling/` | 21アーキタイプ、val 96.5%、温度較正済み |
| 手札・山札・サイド推定 | `ptcg_ai/hidden_information/` | 実装済み。search 連携の入口は `search_adapter.py` |
| 盤面特徴量(ルールベース用) | `ptcg_ai/board_evaluation/` | エンコーダに流用できる |
| リーサル探索 | `ptcg_ai/search/lethal_simple.py` | time_limit_ms 付き。時間管理の参考になる |
| config 切り替え | `configs/` + `core/config.py` | 実装済み |
| ML モデルの学習置き場 | `ptcg_ai/learning/` | 空(ここに実装する) |

## 足りない部品(重要度順)

### 1. 状態・行動エンコーダ(最重要)

Observation → 特徴ベクトル、`select.option` の各選択肢 → 特徴量に変換する層。
ポリシー(模倣)とバリュー(盤面評価)の両方がこれに乗る。

- 選択肢は可変長・可変個なので、固定の行動空間分類ではなく
  **「各選択肢をスコアリングして選ぶ」形式**にする。
- `board_evaluation/` の既存特徴量(attack_features, board_features)を流用する。

### 2. 盤面評価(バリューネットワーク)— 自己対戦なしで作る

リプレイの各局面に「そのゲームの最終勝敗」をラベル付けして勝率予測器を教師あり学習。
行動の模倣より頑健(下手な手を真似るリスクがない)。

**設計の分岐点(要決定):** リプレイには両者の observation があるので神視点で学習できるが、
実戦では相手の非公開情報が見えない。選択肢は:

- (a) 公開情報 + hidden_information の推定値を入力に学習する
- (b) 全情報で学習し、探索時にサンプリングした世界(determinization)に適用する

### 3. 探索との結合(一番勝率が伸びるところ)

`search_begin` API + hidden_information はこのためにある。流れ:

```
相手の山札・手札を推定分布からサンプリング(determinization)
→ 具体化した世界で search_step で数手読み
→ 葉をバリュー関数で評価
→ 複数サンプルの平均で手を選ぶ
```

足りないもの:

- **サンプラー**: hidden_information の推定分布 → `search_begin` の引数形式
  (具体的な相手手札・山札)への変換。`search_adapter.py` が入口。
- **探索中の相手の行動モデル**: 模倣ポリシーをそのまま相手番に適用する
  (「上位プレイヤーならこう動く」)。
- **時間管理**: Kaggle の1手あたり制限内に収める打ち切り制御。
  lethal_simple の `time_limit_ms` と同じ枠組みで。

### 4. 評価基盤

新エージェント vs 現行ルールベースを複数デッキで自動対戦させ、勝率+信頼区間を出すリーグ。

- 過去の 90 試合では足りない。数%の差を検出するには **500 試合以上** 必要。
- これがないと「改善したつもり」の繰り返しになる。

### 5. Kaggle 実行環境での推論制約

- 提出環境で torch 等が使えるか・時間内に収まるかを確認してからモデルサイズを決める。
- 安全策: deck_predictor と同じ **「ローカルで学習 → JSON で重み出力 →
  numpy(or 純Python)で推論」** パターンを踏襲する。

## ロードマップ

1. **エンコーダ + 勝率予測器**(リプレイから教師あり)
   → まず既存ルールベースの評価関数を置き換え/補強
2. **模倣ポリシー**
   → 単体エージェントとして評価。探索の事前分布・相手モデルにも使う
3. **determinization 付き探索**(hidden_information + サンプラー + バリュー葉評価)
   → ここが本命
4. (余力があれば)BC 初期化からの自己対戦ファインチューニング
   → 1〜3 で強くなった後なら「弱い自己対戦」の懸念は解消される
