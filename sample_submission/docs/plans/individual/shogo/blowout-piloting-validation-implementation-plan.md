# 実装計画: ブローアウト負けは piloting か構造か（PolicyModel投資前の検証）

作成: 2026-07-21
状態: 実装計画
前提: loss taxonomy で **ブローアウト負け（サイドレース大差）が負けの69.2%（139/201）で最大**と判明し、routing は「PolicyModel改善」を推奨（[loss taxonomy routing](../../../results/2026-07-21_loss_taxonomy_routing.md)）。
対象ブランチ: `experiment/pimc-hidden-info-integration`

---

## この計画の目的

loss taxonomy は「ブローアウトが最大の敗因で、相手を問わず広く分散、序盤は正常なのに轢かれる」から **PolicyModelの問題** と routing した。これは妥当だが、**山札切れで一度私たちを騙したのと同じ構図**である。あのときも「回し方の問題」と推論したが、決定的検証（第三者が同じデッキで同率に山札切れ）で**棄却**された。

ブローアウトの「広く分散＋序盤正常」というシグネチャは、**PolicyModelが下手**でも、**デッキがメタに対して構造的に遅い/脆い（フーディンはセットアップ系で速いデッキに轢かれるのは構築由来）**でも、どちらでも同じように出る。区別できていない。

さらに、**自チーム勝率は162/363＝44.6%で5割割れ**。「上位デッキ」で勝ち越せていないのは、「回し方が上位に届かない（PolicyModelに伸びしろ）」のか「デッキがこのメタで不利（デッキ選択の問題）」のどちらかを示す。

**目的: PolicyModel改善という大きな投資に踏み込む前に、山札切れを棄却したのと同じ検証（同デッキの第三者プレイヤーの成績比較）で、ブローアウトが piloting で減らせるのか（＝天井がデッキでないか）を安く確かめる。**

---

## スコープ

**やること**: 同アーキタイプ（Alakazam）を回す第三者プレイヤーの (1) 全体勝率 と (2) 負けのうちブローアウトが占める率 を、自チーム（44.6% / 69.2%）と比較し、ブローアウトが piloting で減らせる余地があるかを判定する。

**やらないこと（Non-goals）**:
- PolicyModel の改修そのもの → 本検証で「piloting に余地あり」と出た場合の次フェーズ
- ブローアウト139件の決定レベル深掘り（routing docが挙げた次の診断）→ 本検証が piloting 余地を裏付けてから行う
- `deck.csv` 変更・別デッキ採用 → 本検証が「構造的天井」と出た場合に**別途ユーザー相談で**検討（共有提出物）
- 探索/PIMC・足場固め → 対象外

読み取り専用の分析に徹する。

## 事前確認済みの契約（Contracts）

### 1. 第三者Alakazamパイロットの母集団（既に特定済み）

- `kaggle_replays/_diag_deckout_topplayer_rate.py` の判定を再利用: `kaggle_replays/replays/` の全リプレイをスキャンし、自チーム（`MORIOKA Tsuoi`）以外の各プレイヤー視点の観測に **card_id 743(Alakazam) と 742(Kadabra) の両方**が現れたら「同アーキタイプ」と判定。
- 既に判明している規模: **695ユニークチーム・のべ2515試合・うち負け1157件**（→ 勝ち約1358件）。よって**勝率も算出可能**。

### 2. ブローアウト/接戦/山札切れ/ベンチ壊滅の検出（taxonomy Step1を再利用）

- `kaggle_replays/_diag_loss_taxonomy.py` の相互排他ルール（[definitions](../../../results/2026-07-21_loss_taxonomy_definitions.md)）: 優先順で timeout/error → 山札切れ(`deckCount` が0を記録) → ベンチ壊滅(active・bench両空) → 接戦(最終残りサイド≤2) → **ブローアウト(最終残りサイド≥3)**。敗者自身の視点の最終観測に適用。第三者の負け1157件にそのまま適用できる。

### 3. 比較の基準値（自チーム、確定済み）

- 全体勝率: 162/363 = **44.6%**
- 負けのブローアウト率: 139/201 = **69.2%**
- 負けの接戦率: 10/201 = 5.0%

### 4. 既知の限界（前回の検証で明記済み、本計画でも継承）

- 第三者母集団は Kaggle リーダーボード上位に厳密フィルタしたものではなく、様々な順位帯を含む（`fetch_top_episodes.py` 等が集めた対戦相手全般）。→ Step3 で「勝率上位の部分集団」に絞る補正を行う。
- 同一チームが複数試合を含む（最大133試合）ためクラスタ効果あり。上位数チームを除いた頑健性も確認する。

## ステップ

### Step 1: 第三者Alakazamの全体勝率（piloting余地の一次シグナル）

- 母集団2515試合の勝率を算出し、自チーム44.6%と比較。チーム別勝率の分布も出す。
- 完了条件: `results/2026-07-21_blowout_valid_winrate.md` に第三者勝率（集計＋分布）と自チームとの差。**明確に高ければ「同デッキで上位はもっと勝てている＝piloting余地あり」の一次証拠**。
- 注意: 第三者は自分たちと異なる相手と当たる（マッチメイク差）ため、生の勝率比較は交絡を含む。これは補助指標とし、決定打は Step2 の「負け方」比較に置く。

### Step 2: 第三者の負けのブローアウト率（直接の検証）

- 第三者の負け1157件に taxonomy 検出を適用し、ブローアウト率・接戦率・山札切れ率を算出。自チーム（69.2% / 5.0% / 25.9%）と比較。
- 解釈: **負けに占めるブローアウト率**は勝率と独立に「どう負けるか」を測るため、マッチメイク差に頑健。
  - 第三者のブローアウト率が**明確に低い**（負けが接戦/山札切れ寄り）→ 上手いパイロットは「轢かれる負け」を勝ち/接戦に変えている＝**piloting余地あり**。
  - 第三者も**同率でブローアウト**→ 上位でも大差負けは減らない＝**構造的天井**。
- 完了条件: `results/2026-07-21_blowout_valid_lossmix.md` に第三者の負け内訳と自チームとの比較・判定。

### Step 3: 上位部分集団での補正（前回の限界への対応）

- 母集団を「勝率上位」または試合数の多い実力上位チームに絞り、Step1/2 を再計算。**真に上手いパイロットがブローアウトを避けているか**を、順位帯フィルタなしの限界を補って確認。上位数チームを除いた頑健性チェックも行う。
- 完了条件: `results/2026-07-21_blowout_valid_topsubset.md` に上位部分集団の勝率・ブローアウト率。

### Step 4: 統合と routing

| 検証結果 | 天井の所在 | 次の大投資 |
|---|---|---|
| 第三者（特に上位）が高勝率＋ブローアウト率が明確に低い | piloting（回し方） | **PolicyModel改善**。次は routing doc の「序盤正常なブローアウト94件の決定レベル深掘り」へ |
| 第三者も同勝率・同ブローアウト率 | デッキ×メタ（構造的） | PolicyModel投資は頭打ち。**デッキ選択の見直し**をユーザーと相談（より速い/耐性のあるアーキタイプ） |
| 勝率は上だがブローアウト率は同程度 | 複合（部分的余地） | PolicyModelで拾える分と構造的に諦める分を切り分け、期待効果を見積もってから投資判断 |

- 完了条件: `results/2026-07-21_blowout_valid_routing.md` に、証拠に基づく次の大投資（PolicyModel改善 / デッキ見直し）の判断。

## Definition of Done

- [x] 第三者Alakazamの全体勝率を測り、自チーム44.6%と比較 → [結果](../../../results/2026-07-21_blowout_valid_winrate.md): 54.0%で有意に高い
- [x] 第三者の負けのブローアウト率を同一検出ルールで測り、自チーム69.2%と比較 → [結果](../../../results/2026-07-21_blowout_valid_lossmix.md): 64.0%で有意差なし
- [x] 勝率上位の部分集団に絞った補正で、順位帯フィルタなしの限界に対応 → [結果](../../../results/2026-07-21_blowout_valid_topsubset.md): 頑健性チェックはStep1/2を再現、勝率上位チームでも境界的
- [x] ブローアウトの天井が piloting か構造かを判定し、次の大投資（PolicyModel改善 or デッキ見直し）を証拠でrouting → [結果](../../../results/2026-07-21_blowout_valid_routing.md): 複合判定
- [x] （明示的にやらないこと: PolicyModel改修・94件の深掘り・deck.csv変更・探索・足場固めは未実施のまま維持）

この検証が終われば、taxonomy が指した「PolicyModel改善」に踏み込む前に、**その投資の天井がデッキでないこと**を（山札切れで効いた規律のまま）安く確認できる。piloting余地が裏付けられれば決定レベル深掘りへ、構造的天井なら一段大きなデッキ選択の議論へ、と分岐を証拠で選べる。
