## 1. 評価設定

- **対象データ**: `kaggle_replays/value_net/features.npz` の **test split(split==2)= 68,826 局面のみ**。
  val split(59,169)は学習側の温度較正フィッティングに使用済みのため、最終判断は未使用の test split で行う(design.md §5.1)。
- **推論経路**: 本番の `ptcg_ai.learning.value_model.ValueModel`(較正込み)を評価に用いる。
  全 test 局面を高速に流すためベクトル化した numpy フォワードを使うが、無作為 300 局面で
  `ValueModel.predict_win_prob_from_features` と数値一致することをスポットチェックで担保している
  （最大誤差 **5.6e-16**、実質完全一致）。
- **指標**: AUC / logloss(sklearn、学習パイプラインと同一関数)。test 勝率(正例率)= 0.5321。
- **較正の扱い**: 学習パイプラインが `meta.test_metrics` に記録している数値は **較正前 raw** 出力に対するもの。
  本レポートでは (a) 較正後(ValueModel の実出力)と (b) 較正前 raw の両方を出し、(b) で `meta.test_metrics` との整合を確認する。

### meta.test_metrics との整合性

| 経路 | AUC | logloss |
|---|---|---|
| 本評価: 値ネット raw(較正前) | 0.74456 | 0.59311 |
| `value_weights.json` meta.test_metrics | 0.74456 | 0.59306 |
| 差分 | 3.0e-09 | 4.9e-05 |

raw 経路が学習パイプラインの記録値と一致（差は浮動小数点誤差レベル）。フォワードパス（標準化・W の向き・活性化）と較正式の実装が学習側と同一であることが確認できた。

## 2. 全体結果(test split, n=68,826)

| モデル | AUC | logloss |
|---|---|---|
| **値ネット(較正後・実出力)** | **0.7457** | **0.5865** |
| 値ネット(較正前 raw) | 0.7446 | 0.5931 |
| ベースライン1(prize_diff 1変数ロジスティック回帰) | 0.6821 | 0.6339 |
| ベースライン2(マッチアップ事前勝率表) | 0.5656 | 0.7073 |

- 較正は AUC をほぼ変えず（0.7446→0.7457、帯ごとに単調変換のため順位はほぼ保存）、**logloss を 0.5931→0.5865 と改善**。温度スケーリングが意図どおり確率の過信を緩めている。
- 値ネットは **両ベースラインを AUC・logloss とも明確に上回る**。特にマッチアップ事前勝率表(ベースライン2)は AUC=0.566 とほぼ無識別力で、「相手・自分のアーキタイプだけ」では盤面の勝敗はほとんど説明できない一方、盤面特徴を使う値ネットは 0.75 近い識別力を持つ。

### ベースラインの構築メモ

- **ベースライン1**: `FEATURE_NAMES.index("prize_diff")` の1列だけを説明変数に、train split で `LogisticRegression`(sample_weight は features.npz の weight 列)を学習。係数 -0.443・切片 0.228（サイド差が小さい=自分が取れていない方が不利、という符号で妥当）。
- **ベースライン2**: `kaggle_replays/deck_predictor/output/deck_labels.jsonl`（(episode_id, player_index)→archetype、9,396 行）を結合し、train split で (自archetype, 相手archetype) 別の実勝率表を作成。少数セルが 0/1 に張り付いて logloss が発散するのを防ぐため、擬似カウント K=20 で全体平均(0.527)へ縮小(shrinkage)した標準的な prior 表とした。test 局面の 99% が学習済みペアで被覆。ラベルは全 test 局面に結合できたためスキップは発生していない。

## 3. ターン帯別(値ネット較正 vs ベースライン1)

| ターン帯 | n | 値ネット AUC | 値ネット logloss | ベース1 AUC | ベース1 logloss |
|---|---|---|---|---|---|
| 1-2(序盤) | 10,310 | **0.530** | 0.6932 | 0.499 | 0.7165 |
| 3-5 | 16,819 | **0.656** | 0.6536 | 0.574 | 0.6757 |
| 6-10 | 23,094 | **0.778** | 0.5648 | 0.735 | 0.6034 |
| 11+ | 18,603 | **0.839** | 0.4937 | 0.752 | 0.5881 |

- **全ターン帯で値ネットがベースライン1を上回る**（AUC・logloss とも）。
- design.md §7 の既知リスク「序盤は勝敗との相関が弱く弱いはず」は数値で裏付けられた: **序盤 1-2 の AUC は 0.530 とほぼコイントスに近い**（ただしベースライン1 の 0.499 = 完全に無識別 よりは上）。序盤は盤面がほとんど展開しておらず、prize_diff もほぼ 0 で情報がないため妥当。ターンが進むほど識別力が単調に上がり、11+ では AUC 0.839 に達する。
- 序盤で値ネットがベースライン1を **わずかにしか上回らない**点は、design.md §3.1 が示唆する「序盤向けにマッチアップ特徴を足す」改善余地が残っていることを意味する（後述の推奨参照）。

## 4. マッチアップ別(自archetype、値ネット較正 vs ベースライン2)

主要 archetype（件数上位、`deck_predictor` の分類不能 "other" とラベル欠損 "unknown" は集約バケットへ）を個別に、それ以外を "other" に束ねて比較。

| 自archetype | n | 値ネット AUC | 値ネット logloss | ベース2 AUC | ベース2 logloss |
|---|---|---|---|---|---|
| alakazam(最多) | 23,840 | 0.715 | 0.6174 | 0.567 | 0.6880 |
| mega_lucario_ex | 7,026 | 0.763 | 0.5662 | 0.580 | 0.6900 |
| archaludon_ex | 6,751 | 0.774 | 0.5617 | 0.590 | 0.6859 |
| dragapult_ex | 5,749 | 0.805 | 0.5114 | 0.518 | 0.7405 |
| marnie_grimmsnarl_ex | 5,608 | 0.787 | 0.5615 | 0.537 | 0.6860 |
| crustle | 4,389 | 0.712 | 0.6189 | 0.530 | 0.7201 |
| other(minor + 分類不能) | 15,463 | 0.742 | 0.5869 | 0.564 | 0.7461 |

- **全アーキタイプで値ネットがマッチアップ事前勝率表を大きく上回る**（AUC 差はおおむね +0.15〜+0.29）。
- 差が最も大きいのは **dragapult_ex**(値ネット 0.805 vs 表 0.518、差 +0.29)。マッチアップ表がほぼ無識別なアーキタイプでも、盤面特徴を見る値ネットは高い識別力を保つ。これは「アーキタイプ相性だけでは勝敗が決まらず、実際の盤面展開が支配的」という直感と整合する。
- design.md §8 で重点対象とされた **alakazam(フーディン)は最多(23,840 局面)だが AUC は 0.715 と主要アーキタイプ中では低め**。crustle と並び、盤面から勝敗が読みにくいアーキタイプである可能性がある。フーディン中心運用の観点では、このマッチアップでの改善余地を今後注視したい。

## 5. 判断: **PASS**

design.md §5.1 の基準「自明なベースラインを明確に上回ること」に照らし、**PASS** と判定する。根拠:

1. **全体で両ベースラインを明確に上回る**: 値ネット(較正後)AUC 0.746 / logloss 0.587 に対し、ベースライン1(prize_diff)0.682 / 0.634、ベースライン2(マッチアップ表)0.566 / 0.707。AUC・logloss とも値ネットが上回る。
2. **ターン帯別に全帯でベースライン1を上回る**。序盤(1-2)は AUC 0.530 と弱いが、これは design.md §7 が予告した既知特性であり、同帯のベースライン1(0.499)よりは上。「値ネットが序盤でベースラインに負ける（=盤面特徴が情報を足せていない）」という撤退相当の兆候は出ていない。
3. **マッチアップ別に全アーキタイプでベースライン2を上回る**。相性表がほぼ無識別なアーキタイプでも盤面特徴で識別できており、値ネットの付加価値が確認できた。

留保事項（FAIL ではないが要監視）:
- 序盤(1-2)の識別力はコイントス同然で、実運用で序盤の局面評価に強く依存する設計は避けるべき。
- alakazam / crustle は主要アーキタイプ中で相対的に AUC が低い。フーディン重点運用（design.md §8）では要フォロー。
- 学習・評価とも Kaggle 上位リプレイ由来で分布が偏っている可能性（design.md §7）。オフライン AUC の高さがそのまま対戦強度に直結するとは限らない。

## 6. 次工程への推奨

**config 接続（`configs/ml_value.json`）と対戦リーグ（design.md §5.2）へ進むことを推奨する。** 値ネットはオフラインで両ベースラインを全体・ターン帯別・マッチアップ別のいずれでも明確に上回り、raw 出力は学習パイプラインの記録値と厳密に整合し、本番推論経路 `ValueModel` が評価値と完全一致することも確認できた（実装の正しさは 30 件のゴールデンテストでも担保済み）。中盤以降(6-10 で AUC 0.78、11+ で 0.84)の識別力は盤面評価の置き換え・補強として十分実用的である。ただし序盤(1-2)の弱さは既知の設計限界なので、オンライン評価では「序盤は値ネットに強く依存させない（探索・ルールベースと併用する）」構成を初期案とし、500 試合以上での勝率＋信頼区間（design.md §5.2）で現行 `rule_lethal` に対する非劣化を確認したうえで、序盤向けのマッチアップ特徴追加（design.md §3.1）を次の改善候補として持ち越すのがよい。
