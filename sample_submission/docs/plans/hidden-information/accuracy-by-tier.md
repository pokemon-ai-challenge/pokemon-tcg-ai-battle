# 非公開情報推定レイヤー — ティア別 精度（キャリブレーション）ドキュメント

相手の非公開情報（山札・手札・サイド）推定が「どのくらい正しいか」を、**相手デッキのティア別**に測ってまとめたもの。
「上位デッキ（学習データで多数）ではよく当たるが、中位・下位（少数）の相手ではどれだけ劣化するか」を定量化する。

- 生成元スクリプト: [`kaggle_replays/deck_predictor/evaluate_hidden_information_by_tier.py`](../../../../kaggle_replays/deck_predictor/evaluate_hidden_information_by_tier.py)
- 自動生成レポート（全ティアの reliability 表つき）: `kaggle_replays/deck_predictor/output/hidden_info_eval_by_tier_report.md`
- このドキュメントは自動レポートを人間向けに要約・解釈したもの。

---

## 1. 前提: 何を測っているか

- **自分側（自分の山札・サイド）は測定対象外**。60枚が既知で組み合わせ論だけで厳密に求まるため、定義上つねに正しくキャリブレートされている（誤差ゼロ）。
- **測るのは相手側**（`HybridDeckPredictor` の事後分布 × 代表リスト × 超幾何ゾーン配分）。「相手の手札／山札にこの card_id が入っている確率」の予測が実際どれだけ当たるかを見る。

### 指標: ECE（Expected Calibration Error）
「◯%と予測したとき、実際に◯%当たるか」のズレの平均。**低いほど良い（0 = 完璧に較正）**。
併記する **ナイーブ**（全アーキタイプ等重みの一様事後）を実装が下回っていれば「学習が効いている」と言える。

### データ
- Kaggle リプレイ（`kaggle_replays/replays/`）の実 60 枚デッキ（`deck_db.jsonl`）を ground truth に使用。
- 手札は持ち主自身の視点から真値を復元（追加シミュレーション不要）。
- 山札 ground truth は `全60枚 − 手札 − 公開ゾーン(取得済サイド含む)`。未取得サイドが微量混入する既知の制約あり（完全な正解は神視点ローカル対戦 `battle_review_viewer/hidden_info_diff.py` 側で別途検証）。

## 2. ティア定義（重要: 外部メタTierではなくKaggle実データ頻度ベース）

この branch には明示的なティア表（`meta_decks.py` 等）が無く、推定プールは21アーキタイプ全部をカバーする。
そこで**ティアは「ネットで言われるメタTier S/A/B」ではなく、Kaggleリプレイ実データ（`deck_labels.jsonl`、全9396ラベル）の出現頻度**で定義する。
出現頻度 = 実戦で当たる頻度 ≈ 推定器の学習データ内の相対量、なので「上位で学習している」という状況とも整合する。

| ティア | 区切り | アーキタイプ（出現率） |
|---|---|---|
| **上位 (Top)** | 各10%超 | alakazam (29.9%) / mega_lucario_ex (13.4%) / archaludon_ex (11.5%) |
| **中の上 (Upper-mid)** | 5〜8% | crustle (7.8%) / dragapult_ex (6.7%) / marnie_grimmsnarl_ex (6.3%) / mega_starmie_ex (5.2%) |
| **中の中 (Mid)** | 1〜2% | shirona_garchomp_ex (1.9%) / ogerpon_teal_ex (1.5%) / mega_abomasnow_ex (1.5%) / kamitsuorochi_ex (1.5%) / yadoking (1.3%) / oliva_ex (1.1%) |
| **下位 (Low)** | <1% | mega_froslass_ex / rocket_honchkrow / omatsuri_ondo / takeruraiko_ex / n_zoroark_ex / toxtricity / gekkouga_ex |
| **分類不能 (Other)** | — | 代表リスト無し（推定は「不明カード」扱い） |

**軸**: 意思決定時点を「相手が使っているアーキタイプのティア」で層別する。

## 3. 結果（サマリ）

> 1000リプレイをサンプルした確定値。ECE は 実装 / ナイーブ（低いほど良い）。600本→1000本で数値はほぼ動かず**収束**しており、かつ1本あたりの処理コストがサンプル蓄積で増大するため、全4698本は回さず1000本で確定とした（各ティアのサンプルは数万〜数百万件で十分）。

| ティア | 相手デッキ数 | 意思決定時点 | 手札ECE(実装/ナイーブ) | 山札ECE(実装/ナイーブ) | 実装 vs ナイーブ |
|---|---:|---:|---|---|---|
| 上位 (Top) | 1017 | 67538 | **0.0084 / 0.0116** | **0.0152 / 0.0413** | ◎ 両方勝ち |
| 中の上 (Upper-mid) | 484 | 33735 | **0.0039 / 0.0069** | **0.0258 / 0.0369** | ◎ 両方勝ち |
| 中の中 (Mid) | 301 | 18632 | **0.0026 / 0.0036** | **0.0136 / 0.0479** | ◎ 両方勝ち |
| 下位 (Low) | 83 | 6127 | **0.0049 / 0.0057** | **0.0269 / 0.0347** | ◎ 両方勝ち |
| 分類不能 (Other) | 115 | 9613 | 0.0143 / **0.0030** | 0.0639 / **0.0250** | ✕ 両方負け |

### 結論

1. **実在する全ティア（上位〜下位）で、実装はナイーブを手札・山札とも上回る**。ティアが下がっても単調な劣化は無く、下位デッキ相手でも堅牢（39デッキ/3270時点で確認）。
   → 「上位で学習しているので下位は精度が落ちるのでは」という当初の懸念は、実在デッキに関しては**否定**された。25本スモークで見えた「下位が負ける」兆候はサンプル不足のノイズだった。
2. **本当の弱点は「分類不能(Other)」＝ 代表リストの無いデッキ**。ここだけ実装がナイーブに大きく負ける（山札ECE 0.062 vs 0.025）。原因は下記の過信。
3. ECE の絶対値は実在ティアで 0.003〜0.027 と小さく、全体としてよく較正されている。

### 高確信帯の詳細（山札・実装）

**上位(Top)** — よく較正、最上位帯だけ軽い過信:

| 予測 | 実際の的中 |
|---|---|
| 50–60%（平均56%） | 68% |
| 70–80%（76%） | 82% |
| 90–100%（97%） | **90%**（約7pt 過信） |

**分類不能(Other)** — 過信が崩壊している:

| 予測 | 実際の的中 |
|---|---|
| 50–60%（平均57%） | **27%** |
| 70–80%（75%） | 46% |
| 90–100%（93%） | **58%**（「ほぼ確実」と言って実際は五分強） |

代表リストの無いデッキに対し、推定器が存在しないカードを高確信で「山札にある」と主張してしまう。

## 3.5. 改善: 事後分布の一様混合（`_POSTERIOR_UNIFORM_MIX = 0.15`）

上記の過信への対策として、`OpponentHiddenState._smoothed_normalized_weights()` で**アーキタイプ事後分布を一様分布へ15%だけ混ぜる**平滑化を入れた（`mixed[a] = 0.85·norm[a] + 0.15/K`）。
着想は「一様（=非コミット）の方が OOD デッキには当たる」という §3 の観測そのもの。誤ったアーキタイプのピークを崩し、特定カードへの過信を下げる。`marginals()` と `sample()`（determinization）の両方へ一貫適用。

### 検証（同一500リプレイ before/after、山札ECE）

| ティア | before | mix=0.15 | mix=0.30 | 採用 |
|---|---:|---:|---:|---|
| 上位 | 0.0180 | **0.0099** | 0.0228 | 0.15 |
| 中の上 | 0.0278 | 0.0117 | **0.0105** | 0.15※ |
| 中の中 | 0.0152 | **0.0111** | 0.0251 | 0.15 |
| 下位 | 0.0237 | **0.0109** | 0.0133 | 0.15 |
| 分類不能 | 0.0596 | 0.0490 | **0.0383** | — |

- **mix=0.15 は全ティア・両ゾーン（手札/山札）を一斉に改善**。特に山札の実在ティアで大幅（過信の解消）。
- mix=0.30 は Other をさらに改善するが、実在ティアが過信→過小へ**行き過ぎて悪化**（上位山札は baseline 割れ）。実在ティア（全体の約9割）を最優先し **0.15 を採用**。
- 効かなかった案の記録: `_SMOOTHING_DECAY_PER_MISS` 強化（miss 減衰）は impl をほぼ動かさなかった。Other デッキでも予測アーキタイプは観測カードと噛み合い miss≈0 のため発火しない（過信の原因は観測ミスマッチではなく「予測アーキタイプの未観測カードの主張」）。
- ※中の上のみ 0.30 が僅差で良いが、他4ティアが 0.15 を明確に選ぶため 0.15 に統一。

### 残る課題
Other は改善後もナイーブ（山札 0.019）には未達（0.049）。一様混合は「全体の過信」を均すが、Other 固有の「誤アーキタイプ確信」を根絶はできない（実在ティアと Other は中確信帯で逆向きの miscalibration を持ち、単一の単調補正では両立不可）。完全な解消は predictor 側（other クラスの検出/較正）か、頻出未分類デッキの代表リスト化（§4）が必要。

## 4. 読み方・使い方

- **高確信の予測は割り引く**（[[feedback_conservative_confidence]]）。一様混合(§3.5)で緩和したが、Other デッキの高確信は依然として実際より高め。
- **さらなる改善の的は「分類不能(Other)」**（一様混合では根絶できない残課題）。対策候補:
  ①頻出する未分類デッキを新アーキタイプとして代表リスト化（`build_archetype_pool.py`）、
  ②predictor 側で `other` クラスの検出・確信度を較正する。
- 数値の再生成:
  ```
  cd kaggle_replays/deck_predictor
  python evaluate_hidden_information_by_tier.py --replay-limit 0 --checkpoint-every 200
  ```

---

## 5. 既知の制約
- 山札 ground truth に未取得サイドが微量混入（§1）。完全な正解は神視点ローカル対戦側で別途検証。
- **山札GT不整合率 約45%**: カードが手札を離れてトラッシュ等に着地する一瞬の会計ズレにより、意思決定時点の約45%は山札サンプルからスキップされる（手札サンプルは影響なし）。それでも山札サンプルは各ティアで数十万〜数百万件あり、結論は揺るがない。
- ティア境界は現データ分布のスナップショット。リプレイ再取得で分布が動いたら `ARCHETYPE_TIER` を更新する。
- `other` はアーキタイプ特定不能なので、精度の良し悪しは代表リストの当否ではなく「不明カード」割合に依存する（他ティアと直接比較しない）。

## 6. 残タスク（Backlog）

> 2026-07-20 時点で **一様混合(§3.5)まで完了・デプロイ済み**。以下は未着手の残課題（必須ではなく将来の伸びしろ）。

### T1. 分類不能(Other)デッキの推定改善 【優先度: 中】
- **現状**: 一様混合後も Other の山札ECE 0.049 はナイーブ(0.019)に未達。全体の約1割の相手なので緊急ではないが、唯一ナイーブに負けるゾーン。
- **なぜ一様混合で根絶できないか**: 実在ティアと Other は中確信帯で逆向きの miscalibration を持つため、単一の単調補正では両立不可（§3.5 参照）。予測器が「other」を過小評価し、誤った実在アーキタイプを高確信で選ぶのが根因。
- **対策候補**:
  - ① 頻出する未分類デッキを新アーキタイプとして代表リスト化（`kaggle_replays/deck_predictor/build_archetype_pool.py`）。`other` バケツ自体を小さくするのが最も本質的。
  - ② predictor 側で `other` クラスの検出・確信度を較正（HybridDeckPredictor の温度/しきい値）。
- **受け入れ基準**: Other の山札・手札 ECE が同ゾーンのナイーブ以下、かつ実在ティアが退行しない（同一500リプレイ before/after で確認）。
