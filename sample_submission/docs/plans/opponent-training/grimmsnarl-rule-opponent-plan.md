## 結果サマリ（2026-07-31・全工程完了／採否確定）

Phase 0 実測 → 具体設計(rule-engine-expert) → 実装(python-engineer) → テスト28件PASS(testing-engineer) → 強さ計測(evaluation-scientist, 各 n=400, error 0) まで完了。**動作は完全（5デッキ完走・不正手0件・機構発火確認）だが、相手役としての採用は見送り。**

判定:
- **A. 対模倣（同デッキ・パイロット比較＝採用根拠）**: 5デッキとも Wilson CI 下限 > 50% に**未達**（01/04 は有意に負け越し43%台、02/03/05 はパリティ）。→ **模倣を超えない**。
- **B. 対 production（強さバンド）**: 全デッキ点推定 52.5〜61.75% で**バンド内**（強すぎ問題なし）。
- **C. 交絡分離（模倣 vs production を同条件で計測）**: 模倣はルールベースより対 production で**有意に +10.5〜18pt 強い**（全 p<0.003、Bonferroni 後も有意）。round_robin の 41.7% と B の 56.75% の食い違いは pilot 差でなく純粋なデッキ相性差と判明。

**結論**: round_robin の `marnie_grimmsnarl_ex` 枠は**現行の模倣ポリシーを維持**（ルールベースに差し替えると相手役が弱くなり評価を歪める）。**「専用ルールベース≫模倣」（ドラパルトで成立）は本アーキタイプに転移しない**＝グリムスナールは高使用アーキで強い人間データが豊富＝模倣が既に強い（経験則はデータ量依存）。

**成果物の扱い**: `opponents/grimmsnarl_rule_01..05` は動作正常なので dragapult_rule と並ぶ**追加のルールベース相手（多様性用）として残置は可**。ただし強さアップグレードにはならない。§F の弱体化調整代は不要（強すぎるデッキは無い）。**follow-up（任意・ROI低め）**: 強化は performance-analyst の敗因分析（missed-lethal / attack-plan ビンパッキング取りこぼし疑い）→ logic 改善。天井が模倣同等（ミラー≈50%）のため投資対効果は限定的。先攻/後攻 A/B は要 code toggle で別途。

**回る仕組み（メノコマシラ・エンジン）**:
1. ユキメノコを出す → 毎ポケモンチェックで、自分のマシマシラ/オーロンゲ（＝特性持ち）にも、相手の特性持ちにもダメカン1個。
2. 自軍に溜まったダメカンを、**悪エネ付きマシマシラのアドレナブレイン**で相手にのせ替え → 相手を継続的に削りつつ、**自分のオーロンゲからダメカンを剥がして回復**（＝「オーロンゲが化け物化」）。
3. シャドーバレット（バトル180＋ベンチ30）＋のせ替えで、**複数KO / サイド加速**。

**エネルギーの二重供給（意思決定上いちばん大事）**:
- **パンクアップ**（進化トリガ）= 悪エネ5枚を **マリィのポケモン限定**（ベロバー/ギモー/オーロンゲ/モルペコ）に。
- **手貼り**（毎ターン1回）= マシマシラは「マリィのポケモン」ではない → **悪エネは手貼りでしか付かない**。
  → **手貼りは原則マシマシラ優先**、オーロンゲの攻撃分はパンクアップで賄う、が基本ロジック。

### 1.2 勝ち筋（2プラン、対面で使い分け）
- **プランA: メノコマシラ・コントロール** … ユキメノコ＋マシラ複数面でダメカンを稼ぎ、要所をシャドーバレットで取る。ターンを作る・粘る。
- **プランB: オーロンゲ・アグロ** … 最速アメ進化でオーロンゲ2〜3体を押し付け、シャドーバレット連打で早期サイド。
- ワンパン環境（メガルカリオ等）には**プランBで先殴り**、遅い/耐久対面には**プランA**、が概ねの指針（note 総意）。

### 1.3 弱点（相手として作るとき＝これを突かれると弱い＝そこそこ再現すべき挙動）
- 2進化で立ち上がりが遅い → **盤面完成前のワンパン**に弱い（メガルカリオ不利）。
- 手札干渉が薄い型は事故る。逆に**草弱点**（HP320でも草で半減圏内）。
- ダメカン計算が複雑で**プレイエラーが起きやすい**（＝ルールベース化の価値が高い＝人手だとミスる所を安定させる）。

## 3. 全体設計（dragapult_rule と同じ骨格 ＋ オーロンゲ固有ロジック）

### 3.1 骨格（dragapult 踏襲）
1. `agent(obs)`: 初回（`select is None`）は 60枚デッキを返す。以降は `select.option` を**スコアリング**して降順選択。
2. **カードカウント**: `my_deck` を起点に、手札・トラッシュ・場・スタジアム等の可視情報を引き、**山札/サイド残**を推定（dragapult の `set_card_counts` 相当）。
3. **attack plan（毎ターン先に計算）**: 今の盤面ダメカン＋シャドーバレット＋アドレナブレインで**どの相手をKOできるか / サイド何枚取れるか**を評価し、ボス/入替/ダメカン配置の判断に使う（dragapult の `main_option_proc`／`plan_a`/`plan_b` 相当）。
4. **ハンドスコア / アタッチスコア / セットアップスコア** を context 別に算出。
5. グローバル状態は `state.turn == 0` でリセット（ワーカー再利用でもゲーム間持ち越さない）。
6. league 契約: `agent()` は `Observation`／`dict` 両対応。デッキはモジュール同梱CSVを読み、`--deck-b` と一致させる。

### 3.2 オーロンゲ固有で **新規に必要**な意思決定（dragapult に無い所）
- **進化＝エネ加速**という価値付け（パンクアップ）。進化タイミングとパンクアップ配分の最適化。
- **アドレナブレイン**によるダメカンのせ替え（回復兼打点）と、**いてつくとばり**の受動ダメージを織り込んだ lethal 計算。
- **手貼りはマシマシラ優先**（パンクアップ対象外だから）というエネ配分ルール。
- 2つの勝ちプラン（コントロール/アグロ）の**動的切替**。

## 4. 意思決定モジュール別の方針（＝本方針書の中身）

各項目は「どう振る舞わせるか」を定義。実装時のスコア値は Phase 0（§6）実測後にチューニング。

### 4.1 先攻/後攻（IS_FIRST）
- **後攻を選ぶ**（dragapult も IS_FIRST で「先攻YES」を避ける実装）。ただし紙で後攻を選ぶ最大理由の一つ（わざマシン エヴォリューションでの後攻1進化）は**Kaggleのカードプールに無い**ため、根拠は以下に置き換える:
  - (a) 2進化デッキは1テンポでも早く動きたい。**先攻/後攻それぞれ最初の番でどこまで動けるか（進化・ふしぎなアメ・攻撃・むずむずかふんの可否）は §6 Phase 0 で実測して確定**する（ここがエンジン実装で紙と異なると判断が反転する）。
  - (b) スボミー型（05）は後攻1むずむずかふんでグッズロックが刺さる。
  - (c) 後攻は情報量・グッズ/サポの使用機会で有利。
- 対ワンパン（メガルカリオ等）は後攻の1テンポ遅れが痛いが、オーロンゲはそもそも早期に殴れないため後攻据え置きでよい。
- **決定（Phase 0 反映）**: §6.2 で **turn-1 進化は先後とも不可＝対称**と確定（紙の後攻根拠は消滅）。v1 既定は後攻のまま（人間ガイド＋スボミープラン整合）だが、setup デッキとしては**先攻も有力**なので **eval で先攻/後攻を A/B 計測して最終確定**（§8 決定事項1）。

### 4.2 セットアップ（SETUP_ACTIVE / SETUP_BENCH）
- **バトル場**: スボミーがあれば（05）**スボミー**を置いてむずむずロック狙い。無ければ **マリィのベロバー**（進化元＋くすねるでドロー、HP70で最低限耐える）。
- **ベンチ**: dragapult 同様「後攻でない限りバトル出し過ぎない」を踏襲しつつ、**ベロバー最優先**で複数、次に**マシマシラ**、**ユキワラシ**（メノコ型のみ）。オーロンゲexの完成品をいきなり晒さない。

### 4.3 展開（どのポケモンをベンチに出すか）
理想盤面（note 総意）: **オーロンゲ×2 ＋ マシマシラ×2〜3 ＋ ユキメノコ×1〜2**。
- ベロバー: 序盤に3〜4ライン確保を優先。**なかよしポフィン**（HP70以下たね2枚）で一気に並ぶ。
- マシマシラ: 2〜3体（アドレナブレインの回数＝打点）。悪エネを付ける対象なので早めに。**ただしマシマシラ(HP110)はポフィン対象外**＝確保は**ポケパッド/ヒカリ/素引き**に依存するので、ポケパッドの使い先として優先。
- ユキワラシ→ユキメノコ: メノコ型は1（〜2）。**02（非メノコ型）は出さない**。
- モルペコ: 採用型（02/05）で**終盤の追加打点**として。序盤は不要。

### 4.4 進化（EVOLVE）＆ ふしぎなアメ
- **最優先: ベロバー/ギモー → オーロンゲex**（パンクアップで悪エネが乗る＝最大テンポ）。ふしぎなアメがあれば **ベロバー→（アメ）→オーロンゲ** を積極。
- 2体目・3体目のオーロンゲ進化も価値大。ただし**パンクアップは山札から悪エネを引く**ので、山札の悪エネ残が減ると乗る枚数も**逓減する**（悪エネ9〜10枚。2体目以降は5枚未満／最悪0のことも）。lethal・進化タイミングの見積りは **`min(5, 山札の悪エネ残)`** で計算すること。パンクアップは山札を削る＝**山札切れを早める**点も注意（記憶 `project_deckout_loss_cause`）。過剰進化は**ボス/ワンパンで割られる**なら抑制（dragapult の「dex 過剰進化 -1」相当のガード）。
- ユキワラシ→ユキメノコ: メノコ型はエンジン始動として高優先。**02では該当なし**。
- 05はアメ4なので**進化の閾値を下げる**（最速化）。

### 4.5 エネルギー付け（ATTACH / ATTACH_FROM / パンクアップ配分）
- **手貼り（1/ターン）**: **悪エネは原則マシマシラへ**（アドレナブレイン起動条件＝悪エネがついていること。**各マシマシラ1枚で十分**）。全マシラに1枚行き渡ったら、攻撃に足りないオーロンゲへ。ベロバー/ギモーへの手貼りは基本しない（パンクアップで賄う）。
- **パンクアップ配分（進化トリガ、悪エネ最大 `min(5, 山札の悪エネ残)`）**: バトルのオーロンゲに**まず2（悪悪＝シャドーバレット分）**、残りを**ベンチのオーロンゲ/ギモー**（次ターンの攻撃予約）や**モルペコ**へ。**マシラには乗らない（マリィのポケモンではない＝対象外）**。
- しきい値: バトルが既に攻撃可能なら余剰エネはベンチ準備へ回す（dragapult の attach_score 構造を流用）。

### 4.6 特性使用（ABILITY）
- **アドレナブレイン（マシマシラ、悪エネ必須）**:
  - 使う条件＝**KOを詰める / KO圏に入れる / 自ポケモンからダメカンを剥がして延命**のいずれかに寄与するとき。
  - **のせ替え元**: いてつくとばり等で溜まった自軍ダメカン。**攻撃を受けているオーロンゲだけでなく、危険域まで溜まったマシマシラ(HP110)からも剥がす**（マシラ延命＝エンジン維持。いてつくとばりは毎チェック自マシラも削るため、放置すると自壊してエンジンが枯れる）。
  - **のせ替え先**: attack plan と連動し、**その30で落ちる相手** or **次で落とす高価値ポケモン**（進化元・低HPたね・システムポケモン）。相手ポケモン評価は dragapult `pokemon_score`（サイド枚数×1000＋エネ数＋道具＋進化段階＋HP）を流用。
  - 複数マシラがあれば**合計9ダメカン＝90ダメージぶん**を配分できる前提で lethal 計算（ダメカン1個＝10ダメージ）。
- **にげあしドロー（ノココッチ、02のみ）**: 山札8枚以下でなければ高優先でドロー（dragapult のドロー特性 +40000／no_draw 時 -1 と同じガード）。**引いた後ノココッチ自身と付随カードは山札に戻る**ため、エネ/道具を載せたノココッチでは撃たない・ベンチ枠が一時的に空く点に注意。
- **いてつくとばり**: 受動（選択不要のはず。※Phase 0 で要確認）。**自分のマシマシラ/オーロンゲも毎チェック削る諸刃**で、相手が特性ポケモンを持たない対面では**純自傷**（相手への直接チップにならない）。lethal 計算では「次のポケモンチェックで**相手が特性持ちのときのみ**+10」を**ボーナス**として控えめに織り込む（v1は主計算に入れず現HPベースで判断＝保守的で可）。

### 4.7 攻撃・ターゲット選択（ATTACK / DAMAGE_COUNTER 系）
- **メインワザ**: シャドーバレット [悪悪] 180 ＋ ベンチ1匹30。
- **attack plan（`main_option_proc` 相当）は「アドレナブレインののせ替え＋シャドーバレット」を一括で解く**（＝本デッキの勝ち筋＝1ターンで複数サイドを取るブローアウトを最適化する）。計算する量:
  - バトルへの 180（相手が**悪弱点**なら×2。オーロンゲ自身の弱点は草だが、これは被弾側の話なので攻撃計算には無関係）。
  - **アドレナブレイン配分（複数マシラで最大9ダメカン＝90ダメージ）を変数に含め、のせ替え先も探索対象にする**。アドレナブレインは**攻撃せずともベンチの低HPを単独KO**でき、シャドーバレットのベンチ30と合わせて**複数KO**を作れる。ここを弱く実装すると取りこぼし＝弱い相手になる。
  - **ベンチ30の置き先**: 現ダメカン＋30（＋アドレナブレイン加算）でKO/次ターンKOになるベンチ、または高価値システムを狙撃。
  - 現在の各ポケモンの残HP（＝いてつくとばり/前ターンのせ替えの結果が反映済み）を使う。
  - **サイド枚数の取り切り**を最大化する組合せを選ぶ（dragapult の counter_indices 探索と同型に、**のせ替え先を変数追加**）。
- **マシマシラは攻撃役にしない**: サイコトリップはコスト**超●**だが、5デッキとも入っているエネは**基本悪エネのみ（超エネ0）＝一生撃てない**。マシマシラは**アドレナブレイン専用ボット**と定義し、攻撃計画に含めない（＝**この構築に「こんらん妨害」は存在しない**）。
- **サブワザ（オーロンゲが未完成/エネ不足のとき）**:
  - ギモー どつく60、ベロバー どつく10 / くすねる（ドロー）、モルペコ スパイクホイール（悪エネ×40加算、02/05の終盤フィニッシャ）。
  - dragapult の「攻撃0でも撃つ」問題（記憶 `project_attack_rulebased_hybrid`）を踏まえ、**盤面未展開のうちに手なりで殴らない**ガードを入れる。
- **ターゲットの重み付け**: ミラーや相手にマシマシラがいる対面では、**エンジン（マシマシラ）＞アタッカー（オーロンゲ）**で狙う。マシマシラは**悪弱点**なのでシャドーバレット（悪）が×2で刺さり、エンジンを止められる（相手オーロンゲは草弱点＝悪では等倍）。
- **ボスの狙う先**: 「KOして1サイド＋相手のシステム/育成中アタッカーを場から消す」を両立する的を最優先。本体でボス対象をKO、ベンチ30で別システムを詰める合わせが理想。
- **免疫テーブル**: dragapult の `no_damage_dex`/`no_damage_counter` に相当する「効かない相手」は、オーロンゲ用に**最小限から開始**し、実戦replayで見つけ次第追加（初手から作り込まない）。

### 4.8 サポート選択（1/ターン、use_support 方式）
優先度の目安（盤面ニーズでスコア化、dragapult の use_support 選定を踏襲）:
1. **ボスの指令**（採用型）: attack plan がKOを生むとき最優先（呼び出してサイド加速）。
2. **リーリエの決心**: 手札が細い/サイド6枚時（8ドロー）に主要ドロー。
3. **ヒカリ**: 序盤の**進化ライン一括サーチ**（たね/1進化/2進化を1枚ずつ）。02はヒカリ4で主軸。
4. **ロケット団のラムダ**: ふしぎなアメ/ボス/スタジアム/スタンプ等**必要なトレーナーズを名指しサーチ**。
5. **クセロシキのたくらみ**（02/04）: 相手の手札が厚い/コンボ阻害したいとき（相手を手札3枚に）。
- **グッズ初動（2進化の立ち上がりの背骨。ここが空だと弱すぎる相手になる）**:
  1. **なかよしポフィン**: 山札からHP70以下のたね2枚をベンチへ＝**ベロバー系を一気に複数展開**（対象＝ベロバー/ユキワラシ/モルペコ/スボミー。**マシマシラ(HP110)は対象外**）。序盤最優先級。
  2. **ポケパッド**: ルール持ち以外のポケモン1枚サーチ＝**マシマシラ/ユキワラシ/欠けたパーツ補完**（オーロンゲexは不可）。マシラの主要確保手段。
  3. **ふしぎなアメ**: ベロバー→オーロンゲの最速進化に。05はアメ4で閾値↓。
  4. **夜のタンカ / エネルギーリサイクル(02) / エネルギー転送(02) / ポケギア**: パンクアップで枯れる**悪エネ・サポの再供給**。優先度は低いが後半のパンクアップ維持に効く。選択肢として登録。
- **アンフェアスタンプ**（グッズ、非サポート）: 効果は両者手札を山札へ→**自分5枚・相手2枚**。**自ポケモンが前の番にKOされた（pre_ko）**ときの捲り札として高優先（dragapult の Unfair_Stamp pre_ko +80000 相当）だが、**同時に相手を手札2枚に削る妨害**でもあり、攻めのターンに合わせても強い。
- **山札管理（デッキアウト回避・決定事項）**: 本デッキはパンクアップ（山札から悪エネを抜く）＋リーリエ等の大量ドローで**山札が減りやすい**（記憶 `project_deckout_loss_cause`）。相手役でも自滅デッキアウトは「弱い相手」になるため**回避側に倒す**。dragapult の `no_draw`（山札残≤8で山札を減らす行動を抑制）を、**リーリエの決心・ヒカリ・ラムダ等の山札を掘る札、および不要不急のパンクアップ**にも一般化して適用する。

### 4.9 スタジアム（スパイクタウンジム）
- 場に無い / 相手スタジアムが出ているときに**張り替え**て常設。
- 毎ターンの「マリィのポケモンサーチ」は**進化ラインの不足分**（ベロバー/ギモー/オーロンゲ）を補充。相手も使える効果だが、相手は非マリィなので実質こちら専用。

### 4.10 逃げ・入替（RETREAT / SWITCH）
- オーロンゲ逃げ2は重い。**ふうせん（05）**があれば軽減を活用。
- スボミー/ベロバーがバトルに残って手詰まりなら、ベンチのオーロンゲへ入替（dragapult の `do_switch` 相当：バトルが攻撃役でなく、ベンチに攻撃準備済みがいるとき）。
- **スボミー（05）の投げ方**: 後攻1でむずむずかふん→相手グッズロック。その後は**HP30のスボミーを居座らせない**（無償サイドを与える）。役目を終えたら速やかにオーロンゲ等へ入替。

### 4.12 守備（草弱点・ヒーローマント）— v1でも最低限入れる
- **既知の草アタッカーは優先KO**し、回避可能なら**オーロンゲを草アタッカー正面に置き続けない**（草弱点でHP320でも半減圏内に入る）。
- **ヒーローマント（1159, 02）**は主要アタッカー（オーロンゲ）に装着し最大HP+100。
- 免疫/脅威テーブルの作り込みは §4.7 同様 replay 後でよい。

### 4.11 各種選択（TO_HAND/TO_BENCH/DISCARD/番号 等）
- dragapult と同様、**ハンドスコアの高い順**に手札へ、**低い順**にトラッシュ。番号系は基本最大（多く引く/多く付ける）。
- Reverse-scoring が要る効果（相手に選ばせる系・ラムダ/ヒカリのサーチ対象決定など）は context で分岐。

## 6. Phase 0 実測結果（2026-07-30 実施・確定）

marnie_grimmsnarl_ex `01.csv` を模倣ポリシーで操縦し `rule_based` 相手に12ゲーム、grimmsnarl 側の全 decision（1056件）の select を dump（`kaggle_replays/_phase0_grimmsnarl_probe.py`、ログ `_phase0_grimmsnarl_probe_log.jsonl`）。

> **実装上の必須注意**: エンジンは `select.context` / `select.type` / `option.type` / `area` を **生 int** で返す（`IntEnum` インスタンスではない）。実装側で `SelectContext(int).name` 等に変換して扱うこと。

### 6.1 特性/効果の select シーケンス（確定）
- **パンクアップ（648, 進化時・自動トリガ）**:
  1. `ACTIVATE`（contextCard=648, `YES`/`NO`）＝「パンクアップを使うか」→ **YES**。
  2. `ATTACH_TO`（type=CARD, `select.deck` 提示, `effect`=648, **min0/maxN**）＝山札の基本悪エネを**バッチで複数選択**（最大5枚＝実装は maxCount 全取り）。
  3. 続けて `ATTACH_FROM`（type=CARD, 各 min1/max1, `contextCard`=悪エネ, options=マリィのポケモン）が**選んだ枚数ぶん連続**。付け先の `energies` は各回更新されるので、`attach_score(is_pankup=True)` を毎回読めば「active に2→ベンチ」の配分が状態機械なしで成立（§4.5）。
  - **枚数(0〜5)の COUNT 選択は無い**。マシラは対象外（マリィのポケモンでない）。
  - ※ rule-engine-expert の Phase 0 ログ再精査による確定（初版の「1枚ごと ATTACH_TO→ATTACH_FROM」表記を訂正）。
- **アドレナブレイン（112, マシマシラ）**: `MAIN`→`ABILITY`（マシマシラ）で発動。以降:
  1. `REMOVE_DAMAGE_COUNTER`（type=CARD＝自分の場のダメカン元ポケモンを選ぶ）
  2. `REMOVE_DAMAGE_COUNTER_COUNT`（type=COUNT, 選択肢=1/2/3＝移す個数）
  3. `DAMAGE_COUNTER`（type=CARD＝相手の場の乗せ先ポケモンを選ぶ）
  - マシラ複数体ぶん連続することがある。**`REMOVE_DAMAGE_COUNTER_COUNT` は api.py 抜粋に無い＝エンジンが列挙を拡張済み**（CLAUDE.md の警告どおり）。生 int で来る前提で扱う。
- **いてつくとばり（104, ユキメノコ）**: **完全に受動/自動**（専用 decision は発生しない）。→ 意思決定不要。lethal にだけ織り込む（§4.6）。
- **スパイクタウンジム（1259）**: **毎ターン自動プロンプト**として `TO_HAND`（type=CARD, `select.deck` 提示, **min=0/max=1＝任意**）で来る。MAIN の ABILITY ではない。→ 必要なマリィのポケモンを1枚取る／不要・山札切れ懸念なら min=0 で見送る（§4.9）。
- **ACTIVATE**（21件）: 特性の「使う?」YES/NO ゲート（観測はすべて 648 パンクアップ）。使いたい特性なら YES。

### 6.2 turn-1 ルール（先後判断に直結・確定）
- **EVOLVE / ATTACK が MAIN に出る最速ターン = turn 3**。turn 1（先攻の初手）・turn 2（後攻の初手）には **EVOLVE も ATTACK も出ない**。turn1 の MAIN = PLAY / ATTACH / END（＋状況で RETREAT/ABILITY）。**進化も攻撃も不可**。
- ⇒ **両者とも「自分の最初の番」には進化できない（対称）**。最速オーロンゲ＋攻撃は **先攻=game turn 3 / 後攻=game turn 4**。
- **紙で後攻を選ぶ最大の理由（わざマシン エヴォリューションでの後攻1進化）は Kaggle に存在せず、進化タイミングは対称**。→ §8 決定1 の「対称なら再検討」条件が**発火**。
- **再判断の結論**: 後攻の一択根拠は消えた。setup デッキとしてはむしろ**先攻（着地＋攻撃が1 game-turn 早い）が有力**。ただし後攻は going-second のドロー・情報・スボミー(05)ロックの利あり。→ **v1 既定は後攻のまま**（人間ガイド総意＋スボミープランと整合）**とし、eval で先攻/後攻を A/B 計測して確定**（evaluation-scientist）。IS_FIRST は turn 0 に `YES`/`NO` で提示、後攻にするには「先攻YES」を選ばない（dragapult と同じ）。

### 6.3 残HP・その他 observed contexts
- lethal は dragapult と同じく `pokemon.hp`（現在HP）前提で設計（同一エンジン。最終確認は実装時に1点だけ取る）。
- その他 observed: `SKILL_ORDER`（ポケモンチェックで複数効果の発動順）, `DISCARD_ENERGY`（逃げ/クラッシュ系）, `DRAW_COUNT`, `SETUP_*`, `TO_ACTIVE/TO_BENCH/SWITCH`, `SWITCH` 等。いずれも dragapult と同じ枠組みで処理可能。
- 再現: `python kaggle_replays/_phase0_grimmsnarl_probe.py <games>`（cwd=sample_submission）。

## 8. リスク・未確定事項

### 決定事項（battle-strategist レビューを受けて確定）
1. **先攻/後攻 = v1 既定は後攻、ただし eval で A/B 確定**。§6.2 で turn-1 進化は先後とも不可＝**対称**と確定したため、紙の後攻根拠は消滅。後攻(情報・going-secondドロー・スボミーロック)と先攻(着地＋攻撃が1 game-turn 早い)のどちらが強いかは実測で決める（evaluation-scientist）。
2. **強さバンド = 下限>50%（対模倣）かつ 上限≲65%（対 production）**。相手役として強すぎて評価を歪めない帯に収める（§7.4）。閾値の最終確定は evaluation-scientist。
3. **山札切れ = 回避側に倒す**。no_draw ガードを全ドロー札・過剰パンクアップに一般化（§4.8）。

### 残リスク
- **エンジンの特性提示形式（§6）が未確認**。ここを実測せずスコアを作ると手戻り大 → Phase 0 必須。
- いてつくとばりを lethal 主計算に入れると読み違いが増える → **v1は現HPベース**、受動ダメージはボーナス扱いで保守的に。
