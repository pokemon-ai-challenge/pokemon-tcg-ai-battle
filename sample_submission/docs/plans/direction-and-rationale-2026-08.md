# 意思決定AIの長期ビジョンと 2026-08 の方針 — 経緯と「なぜそれをやっているか」

最終更新: 2026-08-01 / ブランチ: `feature/decision-pipeline-and-deck`

このドキュメントは「**当初の長期方針**」と「**ここ数日で何を・なぜやってきたか**」を、意思決定の理由が
後から辿れる形で残すもの。個別の実装詳細は各 plan / メモリに、ここは**方向と根拠**に絞る。

---

## 1. 最終目標（長期ビジョン）

単に「次に強い1手を模倣する」AIではなく、**認識 → 長期戦略 → ターン目標 → 具体行動を分離した
階層型意思決定AI**を作る。

```
① Belief・相手デッキ/非公開情報の推定
        ↓
② 長期戦略（どう勝つか。速攻/盤面形成/主力育成/妨害/サイドプラン/温存 …）
        ↓
③ ターン目標・サブゴール（このターンで作りたい状態。制約・優先度付き）
        ↓
④ 具体行動（合法手の選択。模倣Policy＋探索＋Value＋必要なら安全制約）
```

**なぜ**: 現状のAIは「現在の盤面から次の1手を直接選ぶ」フラット構造。だが実戦は、目の前の1手だけ
でなく「どの主力を育てるか」「どのサイドプランで勝つか」「今は攻めるより準備か」「どの札を温存
するか」といった**長期戦略とターン目標**が勝敗を分ける。上位者の思考（相手を読む→勝ち筋を立てる→
今ターンの目標を決める→その手順を選ぶ）に近づけるのが最終目標。

**設計原則**（重要なものだけ）:
- 各レイヤーは独立に評価・交換可能。上位の誤りが下位を壊さない。
- 最初から End-to-End 学習しない。各レイヤーを段階的に。**NNを増やす前に教師信号と評価法を定義**。
- 模倣・探索・Belief・RL を対立させず役割分担で統合。

---

## 2. 現実の制約（なぜ「薄い縦串」から始めるか）

- **締切**: コンペ終了まで約2週間（2026-08-01 時点）。数日で見える成果が要る。
- **収束LB判定（既存の実測結論, memory: `project_lb_converged_verdict`）**: 探索(ISMCTS/PIMC)や
  容量の「足し算」は本番LBに**転移しない**ことが反復的に確認済み。フラットな高度化は効かない。

→ 方針: **4レイヤーを一気に作らず、全レイヤーを最小（＝中間層はまずルールで）実装した薄い縦串を
1本通す。** これなら (a) 数日で測れる成果になり、(b) 本物のアーキテクチャの頭金になる（後で各層を
学習版に差し替えても配線は再利用できる）。

---

## 3. 測定の大前提（なぜ「対象選び」が全て）

自己対戦の実測（memory: `project_measurement_protocol`）で判明:
- **真の 50〜52% 帯は 300 試合では測れない**（検出下限 ≈ 5.7pt）。
- したがって**数日で意味のある成果を出すには、今すでに大きく負けている（50%から遠い）対面を狙う**。
  40%→50% は測れるが 51%→52% は測れない。効果量と測定可能性は同じ場所（今負けている対面）に同居。
- さらに **勝率が一致してもローカルsimが実戦の「負けの機構」まで一致するとは限らない**（後述の
  crustle で実証）。ローカル最適化が本番に転移しない一因はこれ。

## 4. 経緯（ここ数日の意思決定と理由）

### 4.1 第1スライス: 山札切れ（対 crustle）で縦串を1本通す
- **選定理由**: crustle は現行best提出でも ローカルfield評価でも **同じ約33%** で負けており、
  「ローカルで測った改善が実戦に転移すると信頼できる唯一の対面」。負け機構も具体（山札切れ）。
- **実装**: config-gated の `_try_deck_sustain`（`ml_policy_agent.py`）＝**アーキテクチャの配線そのもの**。
  Belief(自山切れリスク＋サイド先行)→戦略(詰める/掘る)→サブゴール(回収/ループ抑制)→行動(候補手バイアス)。
  既定OFF・本番不変・unit 29 pass。`_try_lethal`直後・`_try_pipeline`前（リーサル＞温存＞探索）。
- **経緯**: 回復札3枚バイアスは逆効果（Night Stretcher/Lana's Aid は手札回収で deckCount 非増、
  Lana's は Supporter でテンポ損）→ **山札を直接増やすのは Sacred Ash(1129) だけ**と判明し単独に修正
  → さらに「サイド先行時だけ Dudunsparce の Run Away Draw ループを抑える」戦略依存版へ（劣勢では
  抑制しない＝手札=打点を温存）。
- **結果**: 対crustle **Δ+3.8pt**（非有意, 方向は正・avg_turns 短縮＝詰めが速く機構は正）。ただし小さく
  **LB閾値未満**。deckout はローカルcrustle敗因の 1/3（過半はサイドレース負け）。
- **意義/学び**: (a) **足場は動く・本番安全・再利用可＝アーキテクチャの頭金は達成**。(b) デッキの正体を
  把握（Alakazam「Powerful Hand」＝手札枚数×20打点 ＋ Dudunsparce「Run Away Draw」ドローループ）。
  (c) 山札切れ対策は**どの相手でも一定必要**（ユーザー指摘）なので scaffold は残す。

### 4.2 再照準: ブローアウト（支配的敗因 76%）
- **診断**: 全敗因の 69〜76% がサイドレース・ブローアウト。特定対面に集中せず**全方位**で、第三者
  上位も同率に轢かれる（構造疑い）。
- **対アグロ setup 診断（vs mega_lucario）**: 勝敗はほぼ「**勝ち筋 Alakazam が間に合うか**」の一点
  （勝ち100% / 負け25%）。負けは turn11.6・ベンチ1.3・バトル場エネ0.0の**事故スタートで轢かれ**。
- **結論**: これは「特定局面の特定ミス」ではなく **デッキの速度/一貫性**の問題。piloting より前に
  **デッキ構成**を直すべき、と判断。

### 4.3 現方針: deck-tech（一貫性コアの復元）
- **なぜ deck-tech**: このプロジェクトで**実際にLBを動かした唯一のレバーはデッキ変更**
  （alakazam v2 +0.71 / dragapult RL +12.3, memory: `project_lb_converged_verdict`）。診断が根本原因
  （対アグロで Alakazam 育成成功 25%＝遅い）を名指ししている。
- **battle-strategist 分析（実データ照合）**: 現デッキは **名指し相手に効かない tech（Enhanced Hammer 3,
  Wondrous Patch 2）を厚くし、進化コア（Kadabra/Telepath/Rare Candy/Dawn）を上位標準以下に薄めている**。
  これが「組み上がる前に轢かれる」の主因。コアを戻すだけで**対アグロ・ミラー・対Grimmsnarl 全部**が
  速くなる（速い＝Grimmsnarl の2体目を作らせない、にも直結）。
- **対Grimmsnarl（マリィのオーロンゲ）方針**: 悪弱点OHKO＋Froslass特性メタ＋手札干渉の三重カウンター。
  **320の壁は殴らず、Boss's Orders で進化前(Impidimp/Morgrem)を狙撃して2体目を作らせず、単プライズ⇄
  2プライズ交換でレース勝ち。デッキを歪めず 40-45% を狙う**（有利には反転しない）。手札16枚あれば
  Powerful Hand で 320 OHKO も射程内（＝手札を守る/積み直す立ち回りが鍵）。
- **草サブアタッカー: No**（エネルギー非互換で一貫性を壊す＝真の問題を悪化。候補は Tapu Bulu 920 のみ
  記録し不採用）。
- **メタの動き（ユーザーの現況知識）**: 「Alakazam 上位 60.8%」は少し前の環境。**現在はオーロンゲ
  (Grimmsnarl) が多め**（フーディン流行への名指しカウンターとしてシェア増）。→ 対Grimmsnarl を測定の
  **最優先**にする。ただし Plan A（速度）はGrimmsnarl多メタでこそ正しい方向。

## 6. 長期ビジョンとの接続（なぜこのデッキ作業が「本筋」なのか）

- `_try_deck_sustain` の足場は **4レイヤーの薄い縦串そのもの**（config-gated の再利用可能な配線）。
- deck-tech は **勝ち筋（Alakazam）を到達可能にする**＝上位の戦略レイヤーが働く前提を整える。速く確実に
  勝ち筋が立たなければ、②長期戦略も③ターン目標も乗せる土台が無い。
- battle-strategist の立ち回りルール群は、そのまま**レイヤー②③の中身**（「サイド先行なら詰める／
  対アグロは犠牲を前に裏で育てる／Boss で進化前を狙撃」）。次はこれを scaffold に実装していく。
- つまり「デッキ構成 → 立ち回りルール → 足場への実装」は、階層型AIを**具体的なデッキと環境で肉付け
  する作業**であり、長期ビジョンから外れていない。

## 7. 判断の原則（今回 学んだ/再確認した）

1. **50%から遠く、かつローカル=実戦が一致する対面で測る**（測定可能性＋転移性）。
2. **作る前に具体的な機構（smoking gun）を見つける**。拡散的/構造的なら piloting でなく**デッキ**。
3. **1つの名指しカウンター（Grimmsnarl）のためにデッキを歪めない**。一貫性を直す方が全対面に効く。
4. **本番は測るまで不変**（config-gated / 別ファイル候補、既定OFF）。
5. **勝率を主張する前に測定法を通す**（Wilson CI / 効果量 / 十分な試合数）。
