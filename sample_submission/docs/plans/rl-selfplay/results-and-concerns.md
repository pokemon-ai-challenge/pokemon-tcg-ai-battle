# 分散 Self-Play による強化学習: 結果と懸念

対象: `kaggle_replays/rl/distributed/`(実装)/ `fuudin_v1`・`fuudin_v2`(実験)
期間: 2026-07-28 〜 07-31 / 計 154 世代・73,473 試合

## 要約

模倣学習で作った方策(`policy_weights.json`)を出発点に、Kaggle 上で自己対戦を回して
PPO で強化学習した。**固定相手プールに対する勝率は 0.430 → 0.68 まで上がったが、
そこから 100 世代ぶん横ばい。** 追加特徴を入れても平均は動かなかった。

ただし平均が動かない理由は「学習していない」からではない。**伸びた相手と落ちた相手が
打ち消し合っている**ことが計測で分かった。とくに**過去の自分に負け越している**(後述)。

---

## 1. 構成

対戦生成・PPO 更新・評価をすべて Kaggle 上で行い、手元の PC は zip の受け渡しだけを担う。
詳細は `kaggle_replays/rl/distributed/README.md`。

| 項目 | 値 |
|---|---|
| 自分のデッキ | `alakazam_morioka`(フーディン。リプレイ 88753160 から抽出) |
| 相手 | 8アーキタイプ(模倣学習の固定方策)+ 過去の自分3体 |
| 1世代 | 480試合 → PPO 更新(最大480回、KL 0.02 で打ち切り) |
| 評価 | 固定相手200試合 + プール400試合。学習には使わない |
| 所要 | 1世代 10〜47分 |

## 2. 結果

### fuudin_v1(入力166次元・中間層32)

| 世代 | プール平均 |
|---|---|
| v1 | 0.430 |
| v9 | 0.578 |
| v42 | 0.695 |
| **v66** | **0.748(最高)** |
| v100 | 0.657 |

**最初の 50 世代で +0.25。その後 50 世代は上積みなし。**

途中で効いた変更が1つある。**1世代あたりの勾配更新が8回しかなかった**のを 480 回に増やしたら、
横ばいだったものが動き出した(重みの変化量が1世代あたり 0.088 → 0.539)。
収集に8分かけて更新が4秒・8回という配分になっていた。

### fuudin_v2(入力344次元・中間層128)

盤面カードの識別・山札サイドの残り・自分のトラッシュ・相手の型の予測を追加した。
53 世代を回して**プール平均は 0.635〜0.730 で横ばい**。fuudin_v1 の終盤(約0.68)と同水準。

## 3. 懸念

### 3.1 過去の自分に負け越している(最も重い)

fuudin_v2 の v4 → v52 の相手別の変化:

| 相手 | v4 | v52 | 差 |
|---|---|---|---|
| alakazam | 0.771 | 0.886 | +0.114 |
| crustle | 0.514 | 0.686 | +0.171 |
| shirona_garchomp_ex | 0.771 | 0.857 | +0.086 |
| **prev_v9(過去の自分)** | 0.700 | **0.475** | **−0.225** |
| **prev_v15** | 0.750 | **0.475** | **−0.275** |
| **prev_v18** | 0.650 | **0.425** | **−0.225** |
| marnie_grimmsnarl_ex | 0.629 | 0.429 | −0.200 |
| dragapult_ex | 0.914 | 0.771 | −0.143 |

**100 世代以上前の、明らかに弱いはずの自分に勝てていない。**

推測: 固定相手(模倣学習のアーキタイプ8体)を狩る打ち方に特化した結果、同型戦の
立ち回りが犠牲になっている。フーディン同型は同じデッキ同士なので細かい読み合いで
決まるが、そこを捨てて「模倣相手に効く手」に寄っていると考えられる。

**じゃんけん構造(非推移性)に嵌っている疑いが強い。**平均だけ見ていると気づけない。

### 3.2 自己対戦の相手が更新されない

相手プールに自己対戦を 30% 入れているが、**中身は v9 / v15 / v18 で固定**。
AlphaStar のリーグ戦を意図した構成なのに、相手が古いまま止まっているので機能していない。
学習側は「古い自分に勝つ」より「アーキタイプ8体に勝つ」を優先し、同型戦は置き去りになる。

### 3.3 方策が決め打ちに寄っている

エントロピー 0.988(fuudin_v1 開始時)→ **0.54〜0.57**(現在)。
探索が細り、同型戦のような読み合いでは行動が読まれやすい。
エントロピー係数は 0.005 と小さく、維持には足りていない可能性がある。

### 3.4 KL の壁

KL が閾値 0.02 に張り付き、**エポックの打ち切りが常態化**している
(更新回数 480 → 220〜400)。収集は全量やっているのに、そこから取り出す学習量が減っている。

### 3.5 評価の精度が足りない

400 試合の評価は誤差 ±0.05。世代ごとの改善は良くて 0.01〜0.02 なので**見分けられない**。
1つの問いに答えるのに数十世代・十数時間かかる。実際 fuudin_v2 は 53 世代を回して
「変わらない」以上のことが言えていない。

### 3.6 相手が弱く、本番の実力は未測定

相手は模倣学習で作られた固定方策で、勝つための最適化を受けていない
(検証データでの一致率 50〜62%)。**ここへの勝率が本番の順位に対応する保証はない。**
提出ファイルは用意済みだが、リーダーボードでの測定は未実施。

**現状で最も情報量が大きいのは提出して順位を見ることだと考えている。**

## 4. 検証済みの事実(推測ではない)

- **追加特徴は使われている。** 重みの平均絶対値が 0.0295 → 0.0921 に育ち、既存特徴
  (0.0970)と同水準。v1→v54 の変化量も追加特徴が最大。「特徴が死んでいる」わけではない
- **モデルの拡張は挙動を変えない。** 新しい重みを 0 で初期化すれば出力は完全に一致する
  (317決定点で選ぶ手が全一致・スコア差 0)。模倣学習からやり直す必要はない
- **探索(ISMCTS)は予算内で機能しない。** `ismcts-v1-results.md` の実測どおり、
  cg が巻き戻せないため 1 iteration ≈ 130ms。AlphaZero 方式は成立しない
- **`train_v3.py` は温度が 1 以外だと重要度比を誤る。** worker は softmax(scores/T) で
  行動するのに log_softmax(scores) で比を取っている。T=1.3 で比が最大 0.79 乖離。
  `distributed/learner.py` 側は修正済み

## 5. 次の打ち手(いずれも未検証)

| 案 | 狙い | 手間 |
|---|---|---|
| **自己対戦の相手を毎世代更新** | じゃんけんを回す。3.1・3.2 に直接効く | 小 |
| 自己対戦の比率を上げる(30% → 50%) | 同型戦の比重を戻す | 小 |
| エントロピー係数を上げる(0.005 → 0.02) | 探索を回復する | 小 |
| 中間層を 128 → 64 に戻す | 1世代の時間が半分以下に。判断が速くなる | 中 |
| 相手デッキを 01〜05 のランダムに | 特定構築への過学習を防ぐ | 小 |

**推奨は「自己対戦の相手を毎世代更新する」。**観測された問題に直接対応し、実装も
`run.json` の相手指定を更新するだけで済む。

## 6. 実装上の落とし穴(踏んだもの)

同種の作業をする人が同じ穴に落ちないよう記録する。**いずれもログに異常が出ないまま
結果だけ壊れる**種類の失敗だった。

| 症状 | 原因 | 対策 |
|---|---|---|
| 古い設定のまま学習が進む | Kaggle Dataset の新バージョンが反映される前に Notebook が走る | 反映待ち + Notebook 側で世代を突き合わせて即中断 |
| 前の世代の結果を回収してしまう | `kaggle kernels output` は同名ファイルがあると取得を飛ばす | 回収先を毎回空にし、世代を検証してから反映 |
| **古いコードが Kaggle で動く**(3回) | 配布 zip を `git archive HEAD` で作っており、未コミットの修正が届かない | `git status` が挙げる変更をすべて上書きする方式へ |
| 勝率だけ静かに崩れる | 特徴数がモデルの期待と食い違っても、内積が短い側で打ち切られて対戦が続く | 収集前に特徴数を照合して落とす |
| 型の予測が常に 0 | 予測器のクラス名を間違えたが例外を握りつぶしていた | 読み込み失敗は起動時に落とす |

## 7. 再現手順

```bash
# run を作る
python kaggle_replays/rl/distributed/init_run.py --run-id <名前> \
  --learner-arch alakazam_morioka --learner-weights policy_weights.json \
  --workers kaggle --games-per-worker 480 \
  --opponents alakazam archaludon_ex crustle marnie_grimmsnarl_ex \
              mega_lucario_ex rocket_mewtwo_ex shirona_garchomp_ex dragapult_ex

# Kaggle で1世代(収集 → PPO更新 → 評価 → 次世代モデル)
python kaggle_replays/rl/distributed/notebooks/push_kaggle.py \
  --run-dir kaggle_replays/rl/runs/<名前> --full-cycle
```

保存済みの重みは `ptcg_ai/learning/rl_weights_manifest.json` を参照。
