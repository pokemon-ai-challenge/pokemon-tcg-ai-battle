# 強化学習の頭打ちを外すまで: 判断の流れ

対象: `kaggle_replays/rl/distributed/`(実装)/ `fuudin_v3`・`fuudin_v5_advnorm`・`fuudin_v6_all`(実験)
期間: 2026-08-01 〜 08-02 / 計 101 世代・59,520 試合
前提: [results-and-concerns.md](results-and-concerns.md) の続き

## この文書の目的

`fuudin_v2` が 53 世代を回して横ばいだったところから、何を疑い、何を測り、
どれが外れてどれが当たったかを順に残す。**外れた仮説も理由つきで残す**。
同じ道を二度たどらないために書いている。

結論を先に書くと、**モデルの形も学習則も主因ではなく、
「相手1体あたりの試合数」が頭打ちの正体だった**。

---

## 0. 出発点

`fuudin_v2`(入力344次元・中間層128)は 53 世代でプール平均 0.635〜0.730 の横ばい。
[results-and-concerns.md](results-and-concerns.md) が6つの懸念を挙げていた。

まず「追加特徴が使われていないのでは」を潰した。実戦の決定点 1,386 件で、
追加特徴だけを見えなくして選ぶ手が変わるかを数えた。

| 切ったもの | 手が変わった割合 |
|---|---|
| 追加特徴178次元 | **22.4%** |
| 増設した96ユニット | 28.1% |
| v54 全体 vs v1(学習前) | 29.8% |

**特徴は使われていた。** 53 世代で打ち方は 29.8% の場面で変わり、その大半(22.4ポイント)が
追加特徴によるもの。それでも勝率が動かなかったので、**原因は入力の作り方ではなく、
その先にある**と判断した。

---

## 1. 仮説A「中間層を広げたのが悪い」→ 外れ

### なぜそう疑ったか

`expand_model.py --hidden 128` で中間層を 32 から 128 に広げていた。増やした 96 個は
乱数で初期化される。学習済みの重みを調べると、

```
出力層(第2層)の |w| 平均
  引き継いだ32ユニット : 0.8233 -> 0.8388(ほぼ変化なし)
  増設した96ユニット   : 0.0000 -> 0.5219
  出力への寄与シェア   : 旧32 = 35% / 新96 = 65%
```

**出力の 65% が、乱数から始めたユニット経由に移っていた。** 100 世代かけて育てた
32 ユニットの表現を、53 世代しか鍛えていない粗い表現が押しのけた形に見えた。
つまみの数も 17,857 -> 63,777(3.6倍)に増えている。

### 検証: `fuudin_v3`

`v100` から出発し、**追加特徴はそのまま・中間層だけ 32 に戻して** 52 世代回した。
`fuudin_v2` と出発点も相手プールも設定も同じで、違いは中間層だけ。

### 結果: 差が無い

```
プール平均(13点)
v4 0.710  v8 0.685  v12 0.703  v16 0.735  v20 0.735  v24 0.730  v28 0.715
v32 0.730 v36 0.718 v40 0.698  v44 0.743  v48 0.720  v52 0.682

前半 v4-v24   0.716 ±0.018 (2400試合)
後半 v32-v52  0.715 ±0.018 (2400試合)
差            -0.001 ±0.026
```

**中間層を戻しても頭打ちの位置は変わらなかった。** 仮説Aは棄却。
「出力の65%が新ユニットに移っていた」は事実だが、勝率を決めていた要因ではなかった。

### 途中で分かった別のこと

- **エントロピー低下(0.544 -> 0.462)も KL の張り付き(全世代 0.0200)も、中間層とは無関係。**
  results-and-concerns.md §3.3・§3.4 はモデルの形を変えても消えない
- **打ち消し合いは過去の自分がいなくても起きる。** アーキタイプ8体だけでも、
  苦手な相手が上がった分だけ得意な相手が下がった(ばらつき 0.186 -> 0.144、平均は不動)

### 副産物: PPO 更新の高速化

この実験の途中で、1世代 71 分のうち 69 分が PPO 更新だと分かった。原因は2つ。

- 選択肢を「決定点 × 最大選択肢」の四角にゼロ詰めしていた。選択肢は平均 7.5 個に対し
  最大 42 個あり、**計算の 82% が存在しない選択肢のゼロ**だった
- 第1層の入力は `[盤面 | 選択肢 | カード埋め込み]` で、`W·[s|o|e] = W_s·s + W_o·o + W_e·e`
  と分けられる。`W_s·s` は同じ決定点のどの選択肢でも同じ値なのに、選択肢の数だけ
  繰り返し計算していた

どちらも計算結果を変えずに直せる(実シャードで logp 最大差 1.11e-05、勾配の相対差 8.09e-07)。
**PPO 更新 4157 秒 -> 118 秒、1世代 71 分 -> 12 分。** 以降の実験速度がここで決まった。

## 2. 仮説B「critic が相手を見ていないので褒め方が歪む」→ 外れ(ただし事実は正しい)

### なぜそう疑ったか

仮説Aが外れたので、勝率を決めているのは「何を良い手と教えているか」だと考えた。
学習済み critic を実データで調べると、

```
勝敗との相関(480試合)
  序盤(最初1/4)  0.31
  終盤(最後1/4)  0.69
```

**序盤の局面から勝敗をほとんど当てられていない。** さらにブロックごとに入力を潰すと、

```
潰したブロック                |Δv|平均
相手を示すもの全部(119次元)    0.14
自分の山札/サイド残り(23次元)  0.63   ← 4.5倍
```

**critic は相手が誰かをほとんど価値に反映していない。** その結果、

- 得意な相手 … 実際の勝率が予測を上回るので、どの手も advantage がプラス
- 苦手な相手 … 逆に、どの手もマイナス

となり、**手の良し悪しではなく相手が誰かで褒め方が決まる**。実際に測ると、相手別の
advantage の平均は最大 0.168 ずれていた。

### 検証: `fuudin_v5_advnorm`

advantage を全体でまとめて正規化していたのを、**相手ごとに**正規化するよう変えた。
`fuudin_v3` とビット単位で同じ出発点から 24 世代。

実装は狙いどおり働いた(相手別の平均の絶対値 0.168 -> 0.000、相手が1種類のときは
従来と完全一致)。

### 結果: 差が無い

```
v4-v24 まとめ   fuudin_v3 0.716 / fuudin_v5 0.697
差              -0.020 ±0.026(2400試合ずつ)
```

**下駄を消しても頭打ちは動かなかった。** 相手別の動きも `fuudin_v3` と同様に混在し、
ばらつき(0.139 -> 0.143)も変わらなかった。

## 3. 2回続けて外れたことから見えたこと

仮説A・Bはどちらも「モデルの形」「学習則」を触る手だった。両方とも空振りし、
一方で**共通して観測されたのは付け替え**だった。

```
fuudin_v3 相手別 v4 -> v52
  marnie_grimmsnarl_ex   0.340 -> 0.440   +0.100
  alakazam               0.740 -> 0.840   +0.100
  shirona_garchomp_ex    0.900 -> 0.760   -0.140
  mega_lucario_ex        0.640 -> 0.540   -0.100
```

上がった分だけ下がる。ばらつきだけが縮み、平均は動かない。

ここで**割り算をやり直した**。

```
1世代 480試合 ÷ 相手8体 = 相手1体あたり 60試合/世代
方策のつまみ 23,553個 を 8体で共有
```

相手別の立ち回りを覚えるには相手別のデータが要る。勝率 0.02 の差を見分けるのに
数千試合必要なところ、**60試合しかない**。勾配は一番損の大きい相手へ向かい、
共有部分を動かすので他が巻き添えになる。

**足りないのは容量でも学習則でもなく、相手1体あたりの材料だった。**
中間層を 128 に増やしても直らなかったことが、その裏づけになっている。

## 4. 打ち手を「データ量を変える」側へ切り替えた

ここまでで残っていた手を4つ入れた。時間の都合で同時に投入したため、
**個別の寄与は切り分けられていない**(下記「未解決」参照)。

### 4.1 相手を1体に絞る(効果の本命)

相手を `marnie_grimmsnarl_ex` 1体にした。8体で唯一 0.5 を大きく割っていた最も苦手な
相手で、伸びしろが一番大きい。提出時は型予測(確信度 0.96)で切り替える前提。

### 4.2 Kaggle を2台に

`push_kaggle.py` に `--worker-id` / `--skip-dataset` / `--fetch-only` を足し、
Notebook を worker ごとに別 slug にした。2台を同時に走らせ、シャードを集約して
1回の PPO 更新にする。

```
相手1体あたりの試合数   60/世代  ->  960/世代 (16倍)
```

### 4.3 サイド落ちと山札の記憶

追加特徴の `deck_prize_remain` は「デッキリスト − 見えているゾーン」で、
**山札にあるのかサイドに落ちているのかを区別していなかった**。
区別には「山札サーチで見たとき無かった」という過去の観測が要るが、学習用の encoder は
current 盤面のみから作る設計で、決定点をまたぐ記憶を持たない。

一方で `hidden_information/own_hidden_state.py` の `OwnHiddenState` が、まさにこの推定
(山札サーチによる決定的な消し込みと、未確定分の超幾何計算)を既に実装していた。
rule_based / ml_policy_agent は使っていたが、**学習経路からだけ呼ばれていなかった**。

これを繋いだ。プロファイル `fuudin_v4`(A ブロックを「残り枚数 / 山札にある確率 /
サイドにある確率」の3本立てに)。盤面 344 -> 389 次元。

実戦6試合で山札サーチ 59 回すべて検出、サイド確定枚数と伏せサイド枚数の検算は
不一致 0 件。1ターン目のサーチでサイド6枚の中身が特定できることを確認した。

### 4.4 報酬の密化(PBRS)と価値のクリッピング

報酬が勝敗の1ビットだけなので、サイドの取り合いをポテンシャルにして
`F(s,s') = γΦ(s') − Φ(s)` を各手に足した。この形なら1試合ぶんの合計が定数に畳まれ、
**理論上は最適な方策を変えない**(実装で検算: ずれ 9.99e-16)。

ただし**効果は限定的**だと分かっている。サイド差は序盤に動かないので、
|advantage| の序盤/終盤比は 0.73 -> 0.66 とむしろ偏りが広がった。
critic の序盤の盲点(相関 0.31)には届いていない。

代わりに既存の学習済み勝率予測器(`value_weights.json`)をポテンシャルに使う案も測ったが、
**序盤の相関は 0.163 で RL の critic(0.323)より悪く**、採用しなかった。
この予測器は 166 次元の既存特徴しか見ておらず、カードの識別が入っていないため、
序盤を当てる材料をそもそも持っていない(較正温度もターン1-2で 2.49 と大きく、
学習時点で序盤は当たらないと分かっていたことを示している)。

価値のクリッピング(`value_clip`)は標準的な PPO にあるが本実装に無かったので足した。
critic が −0.58 や 1.767 を出していた(報酬は 0 か 1 しかない)。

## 5. 結果: `fuudin_v6_all`

```
                fuudin_v3    fuudin_v5    fuudin_v6
世代                52           24           25(継続中)
1世代の試合数       480          480          960
相手                8体          8体          1体
相手あたり/世代     60試合       60試合       960試合
```

### 学習の様子が変わった

```
              fuudin_v3 / v5        fuudin_v6
KL            0.0184〜0.0201        0.0115〜0.0136
              (閾値0.02に張り付き)   (届かない)
更新回数       308〜480(打ち切り)    480(全世代完走)
エントロピー   0.544 -> 0.462        0.600 -> 0.543
```

**KL の壁が外れた。** 材料が2倍になり、1回の更新で方策が動く量が減ったため。
探索の細り方も緩やかになった。results-and-concerns.md §3.3・§3.4 は、
**データ量を増やすと軽くなる**性質の問題だったことになる。

### 勝率が動いた

```
収集勝率(前半と後半をまとめた比較)
  fuudin_v3   前半 0.682 / 後半 0.683   差 +0.002 ±0.012  (24,960試合)
  fuudin_v5   前半 0.681 / 後半 0.690   差 +0.008 ±0.017  (11,520試合)
  fuudin_v6   前半 0.491 / 後半 0.530   差 +0.039 ±0.013  (23,040試合)  ← 有意
```

`fuudin_v6` の傾きは **+0.0035 / 世代**。24 世代で marnie 戦が 0.45 帯から 0.55 帯へ。

学習に使っていない評価対戦でも、同じ向きに動いている。

```
評価(marnie 400試合・greedy)
  v8   0.482 ±0.049
  v16  0.550 ±0.049
  v24  0.573 ±0.048
  v8 -> v24  +0.090 ±0.069  ← 有意
```

**苦手だった相手に勝ち越しへ転じた。** 3点とも単調に上がっており、収集勝率の上昇と
向きが一致している。

(v3 / v5 と v6 は測っている相手が違うので、勝率の絶対値は比較できない。
比べているのは「同じ run の中で動いたかどうか」)

## 6. 未解決・注意点

- **4つ同時に入れたので、個別の寄与は不明。** 相手1体化・2台化・サイド落ち・報酬の密化の
  どれが効いたかは分からない。ただし KL とエントロピーの改善は「試合数2倍・相手1体」で
  説明がつく。切り分けるなら設定1つずつ戻して回す(それぞれ無効にできる形にしてある)
- **8体プールでの強さは未測定。** marnie に特化した分、他の相手が落ちている可能性がある
- **v0(= v100 の打ち方)との直接対戦をやっていない。** 最終世代との直接対戦が最も確実な確認
- **critic の序盤の盲点(相関 0.31)は手つかず。** 序盤に効くポテンシャルを作るには、
  追加特徴つき(344次元以上)で勝率予測器を学習し直す必要がある。半日〜1日規模
- **相手は模倣学習の固定方策のまま。** results-and-concerns.md §3.6 のとおり、
  ここへの勝率が本番の順位に対応する保証はない。どこかで提出して順位を見る必要がある
- **標準化の直しは未着手。** 追加178次元は平均0・標準偏差1の決め打ちのままで、
  実データでは特徴ごとの大きさが 6,437 倍ひらいている。まれにしか立たない特徴
  (相手を見分ける側)が systematically 弱く扱われる。重みを付け替えれば出力を変えずに直せる

## 7. 教訓

- **「効いていない」と「使われていない」は別。** 追加特徴は 22.4% の場面で手を変えていた。
  使われた上で勝率が動かないなら、原因は入力より下流にある
- **平均だけ見ない。** 相手別に分けて初めて「付け替え」が見えた。ばらつきが縮んで平均が
  動かないのは、学習が進んでいないのではなく、進む先が無い状態
- **割り算をする。** 「1世代480試合」ではなく「相手1体あたり60試合」で見た瞬間に、
  容量を増やす手が全部見当違いだと分かった
- **測れない実験はしない。** 相手別50試合の誤差は ±0.14。世代ごとの改善 0.01〜0.02 は
  最初から見えない。相手を絞ったことで評価の誤差も下がり、判定できるようになった
