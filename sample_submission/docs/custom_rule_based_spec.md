# カスタムルールベースAI 仕様書（フーディンデッキ）

対象デッキ: `sample_submission/deck.csv`（フーライン・ノコライン・シェイミを中核とする
フーディンのハンドパワーデッキ）。
実装場所: `sample_submission/ptcg_ai/custom_agent/`（`ptcg_ai/core/agent.py` の
`AGENT_TYPE = "custom_rule_based"` から呼ばれる、既存の汎用プロファイル駆動エンジン
`ptcg_ai/rule_based/` `decks/new_deck/` とは独立した実装）。

---

## 1. 定義

- **フーライン**: ケーシィ(741) → ユンゲラー(742) → フーディン(743) の進化系列。
- **ノコライン**: ノコッチ(65) → ノココッチ(66) の進化系列。
- **シェイミ**: 343。

## 2. ポケモンの優先順位

上から優先順位が高い（展開・エネルギー付け・気絶後の後継など、ポケモン全体の優先順位として共通で使う）。

1. フーライン — 進化過程でドロー（サイコドロー）+メイン攻撃（ハンドパワー）を兼ねる中核ライン。
2. ノコライン — 特性（にげあしドロー／ランドクラッシュ）によるドロー要員。
3. シェイミ — 特性はなのカーテンでベンチを守る。

ノココッチ・シェイミは原則ベンチに固定し、自分から場（バトル場）に出さない
（にげる先・気絶後の後継としても他に候補が無い場合のみ）。

## 3. エネルギー

- **リッチエネルギー(13, ACE SPEC)**: 必ずノコラインにつける。
- **カード優先順位**:
  - フーライン個体（741/742/743いずれか）でエネルギーが付いている数が **2体未満**の場合:
    1. テレパス超エネルギー(19)
    2. 基本超エネルギー(5)
  - **2体以上**の場合:
    1. リッチエネルギー(13)（ただしノコライン対象のときのみ。フーライン/シェイミには
       リッチエネルギーは使わない）
    2. テレパス超エネルギー(19)
    3. 基本超エネルギー(5)
- 各ポケモンの必要エネルギー数以上はつけない。
- 手元に候補があるならメイン（バトル場）→場（ベンチ）の順で優先してつける。

必要エネルギー数:

| ポケモン | 必要数 |
|---|---|
| フーライン（進化段階問わず） | 1 |
| ノコッチ | 2 |
| ノココッチ | 3 |
| シェイミ | 2 |

## 4. グッズ

| カード | 使用条件 |
|---|---|
| ふしぎなアメ(1079) | バトル場がケーシィ、かつ手札にユンゲラーが無くフーディンがある場合 |
| 改造ハンマー(1081) | 相手のバトル場のポケモンにエネルギーが付いている場合 |
| なかよしポフィン(1086) | ケーシィ・ノコッチのうち、場・手札に無いものをそれぞれ1枚ずつ引く。両方すでに場・手札にある場合はケーシィの2枚目以降、またはノコッチの2枚目を優先する |
| 夜のタンカ(1097) | 基本（たね）ポケモンを引く。`OPENING_BENCH_PRIORITY` の並びに準拠しつつ、場・手札に進化先が無いポケモンの回収を優先する |
| せいなるはい(1129) | トラッシュにポケモンが3体以上いる場合に使用する |
| ワンダーパッチ(1146) | 手持ちにエネルギーが無く、トラッシュに基本【超】エネルギーがあれば使用する |
| ポケパッド(1152) | 手札にあれば使用する |

## 5. サポート

| カード | 使用条件 |
|---|---|
| トウコ(1225) | 手札にあれば使用。エネルギーはリッチ→テレパス超→基本超の順で優先してサーチ。進化ポケモンは、場・手札を合わせて進化先が無いラインがあればそれを優先。それ以外はフーライン→ノコラインの順 |
| ヒカリ(1231) | 手札にあれば使用。サーチ対象はポケモン優先順位（2章）に沿う |
| ボスの指令(1182) | 「ボスの指令の仕様」参照。攻撃の直前に判断する |
| スイレンのお世話(1184) | (トラッシュにエネルギーがあり、バトル場のエネルギーが足りず、手札にもエネルギーが無い) または (トラッシュにフーディン・ユンゲラー・ケーシィの3体がそろっている) 場合に使用 |
| クセロシキのたくらみ(1197) | 相手の手札が10枚を超えていたら優先的に使用する |

### ボスの指令の仕様

攻撃の直前に判断する。

1. 自分の出せるダメージが、相手のバトルポケモンのHPを下回っていて、かつ相手のベンチ
   ポケモンいずれかのHPを上回っている場合 → 使用する（この2体を交換）。候補が複数ある
   場合は、エネルギーが多くついている方を優先し、次にサイドを多く取れる方を優先する。
2. 自分の出せるダメージが相手の場の全ポケモンのHPを上回っている場合:
   - 相手アクティブがEXでない場合: ベンチにEXポケモンがいれば使用する。いなければ使用しない。
   - 相手アクティブ・ベンチ両方がEXの場合: ベンチの方がエネルギーが多くついていれば使用する。
   - 場にEXが1体もいない場合: エネルギーが一番多くついているのがベンチであれば使用する。
3. 上記のいずれにも当てはまらない場合は使用しない。

> **実装上の注意（仕様の未記載部分）**: 「相手アクティブがEXで、ベンチにEXがいない」組み合わせ
> は仕様に明記が無いため、実装では保守的に「使用しない」としている
> （`ptcg_ai/custom_agent/supporters.py::boss_orders_target`）。

## 6. スタジアム

- バトルコロシアム(1264): 場のスタジアムがバトルコロシアム以外なら、手札にあれば出す。

## 7. 気絶後の後継優先順位

フーライン → ノコライン → シェイミ（2章のポケモン優先順位と同じ）。

## 8. 全体メモ

- サポート・グッズのドロー効果はポケモンまたはエネルギーのみが対象なので、優先順位は
  上記の並びに準拠する。
- 山札の残り枚数を意識する: 手札が20枚以上の場合は、山札からドローする（消費する）
  グッズ・サポート（なかよしポフィン・ポケパッド・トウコ・ヒカリ）を追加では使用しない。
- ノコッチ→ノココッチのループ（毎ターン1体ノココッチへ進化させ、特性で3ドロー後に
  自身を山札へ戻す）を継続する。
- 基本的な立ち回りは、できるだけ手札を多くしてフーディンのハンドパワーで攻撃する。
- ベンチは2枠を確実にノコッチ・ノココッチ用に確保する。

## 9. 立ち回りの優先順位（実装時に設計、`main_turn.py`）

1ターン中、MAINの選択が求められるたびに毎回このパイプラインの先頭から再評価する
（1回のツールコールで1アクションだけを返し、ターンが終わるまで繰り返し呼ばれるゲーム
エンジンの仕様に合わせている）。

1. **確定リーサル攻撃**: 今の攻撃で相手のバトルポケモンを倒しきり、勝利が確定する
   （このKOで自分の残りサイドが0枚になる）なら最優先で攻撃する。
2. **特性**: にげあしドロー等、使える特性があれば使用する（手札20枚以上なら見送る）。
3. **進化**: フーディン系列 → ノココッチ の順で進化させる。
4. **ふしぎなアメ**: 条件成立時、進化の直後の枠として評価する。
5. **グッズ**: なかよしポフィン → 改造ハンマー → ワンダーパッチ → 夜のタンカ →
   せいなるはい → ポケパッド の順で、条件を満たす最優先のものを使用する。
6. **エネルギー付け**（1ターン1回）: 3章のカード優先順位に従い付ける。
7. **にげる**: フーラインがバトル場に出ていないときのみ検討する（フーラインが出ている間は
   被弾リスクがあってもにげない）。ノコッチがバトル場にいて手札にノココッチがある場合は、
   進化すれば特性で自身が山札に戻るためにげなくてよい。それ以外でベンチに明確に優れる
   後継（`KO_REPLACEMENT_PRIORITY` 参照）がいる場合ににげる。
8. **サポート**（1ターン1枚）: この時点（進化・エネルギー付け・にげるが全て終わった後）で
   ボスの指令の条件を再判定し、成立していれば最優先で使用する。不成立ならクセロシキの
   たくらみ（相手手札>10）→トウコ→ヒカリ→スイレンのお世話の順で検討する
   （山札を消費するトウコ/ヒカリは手札20枚以上なら見送る）。
9. **スタジアム**: バトルコロシアム以外なら手札にあれば出す。
10. **攻撃**: 使える技の中から相手のバトルポケモンへの最大ダメージを与える技を選ぶ。
11. **ターン終了**。

コード上は6〜7番（エネルギー・にげる）を8番（サポート）より先に置いている。これは
「ボスの指令は攻撃の直前に判断する」という仕様どおり、その時点でのエネルギー付け・
にげるが反映された最終的な盤面状態でボスの指令を判定させるため（先に他のサポートを
使ってしまうと1ターン1枚の枠を消費してしまい、後からボスの指令が使えることが分かっても
手遅れになるのを防ぐ）。

## 10. トグル機能（ON/OFF切り替え可能）

以下の2つは既定でOFF。現在のルールベースの意思決定には影響しない独立した追加機能で、
それぞれのモジュールのフラグを `True` にすると有効化される。

### 相手デッキ予測 (`ptcg_ai/custom_agent/matchup.py`)

```python
matchup.ENABLE_OPPONENT_DECK_PREDICTION = True
```

有効化すると、既存の相手デッキ予測（`ptcg_ai.opponent_modeling.tracker`。汎用インフラの
再利用）が「確信を持てた」と判定したアーキタイプに応じて、シェイミ・改造ハンマーの
優先度を加点/減点する（ベンチ狙撃技を持つ相手にはシェイミを優先、単体攻撃のみの相手には
シェイミを温存する 等。加点表は `decks/new_deck/deck_plan.py` の対アーキタイプ分析を踏襲）。

### 確定リーサル探索 (`ptcg_ai/custom_agent/lethal_search.py`)

```python
lethal_search.ENABLE_LETHAL_SEARCH = True
```

有効化すると、既存の探索インフラ（`ptcg_ai.search.lethal_simple` +
`ptcg_ai.hidden_information.search_state_stub`）を使い、進化・エネルギー加速・複数体キルなどを
組み合わせた複数手の確定リーサルを、残りサイドが少ない場面（既定: 2枚以下。
`configs/rule_lethal.json` の `lethal_search.max_remaining_prizes` で変更可）で探索する。
OFFのときは `main_turn.py` の簡易リーサル判定（今のターンの1手で倒し切れるかのみ）だけで動く。
