# リーサル探索 起動条件の比較 (issue #58)

- 日付: 2026-07-17
- ブランチ: `feature/lethal-search-phase2`
- 実験方法: ランダム同士の対戦 40 ゲーム × 3 設定。両プレイヤーとも、自分のサイド残り枚数が閾値以下の選択で `lethal_simple.search()` を呼び、リーサルが返ればそれに従う。それ以外はランダムな合法手。
- config: `time_limit_ms: 100` / `max_depth: 20` / `max_nodes: 10000` / `verify_shuffles: 1`
- 再現: scratchpad の比較スクリプト（`tests/integration/test_lethal_search.py::_play_probe_game` と同じ手順）

## 結果

| 設定 | 発火ゲーム数 | 発火時勝利 | 誤検出 | search回数 | リーサル発見回数 | タイムアウト | 平均探索時間 | 最大探索時間 |
|---|---|---|---|---|---|---|---|---|
| 無効 | 0 | - | 0 | 0 | 0 | 0 | - | - |
| サイド残り1枚で起動 | 4 / 40 | **4 / 4** | 0 | 40 | 12 | 25 | 71.2 ms | 100.5 ms |
| サイド残り2枚以下で起動 | 9 / 40 | **9 / 9** | 0 | 62 | 22 | 25 | 47.4 ms | 103.1 ms |

- 「発火ゲーム数」= 探索がリーサルを返したゲーム数。「発火時勝利」= そのゲームを発火プレイヤーが勝った数。
- 「リーサル発見回数」は同一ターン内の再探索（行動列を1手ずつ返すため毎選択で再実行）を含む。
- ターン持ち越し（リーサル主張後に相手へターンが渡ったケース）は 0。
- 検証リプレイ（`verify_shuffles: 1`、非公開情報をシャッフルし直して同一手順の勝利を再確認）による棄却は 0。
- ノード数上限 (`max_nodes: 10000`) への到達は 0。制限はすべて時間 (`time_limit_ms: 100`) 側で発生。

## 考察

- 2枚以下起動は1枚起動に対して発火機会が約2倍になり、誤検出は増えなかった。`State.result` による勝利判定なので、ex / メガシンカex の複数サイド取得も追加コストなしで拾えている。
- タイムアウト率は約40%（リーサルが存在しない局面で時間を使い切るケース）。1回あたり最大 ~100ms で打ち切られ、fallback するだけなので実害はない。
- `max_time_ms` が上限を数 ms 超えるのは、打ち切り判定の粒度（1ノード展開単位）によるオーバーヘッド。
- ゲーム全体の実行時間: 無効 2.4s / 1枚 5.2s / 2枚以下 5.4s（40ゲーム合計）。2枚以下へ拡張しても対戦全体への時間影響はほぼ増えない。

## 結論

`max_remaining_prizes: 2`（サイド残り2枚以下で起動）を既定とする。上限値は `time_limit_ms: 100` / `max_depth: 20` / `max_nodes: 10000` を維持。
